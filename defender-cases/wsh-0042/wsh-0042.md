## WSH-0042 Tykit Phishing Kit Detection

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0042 Tykit Phishing Kit Detection"_ has been created and how to use it.

### Required Access

These hunting cases are linked through a published application that grants us permission to perform threat hunting via the API in our customers' security portals.

## Overview

This KQL query is designed to detect possible TyKit malware network activity on Microsoft Defender for Endpoint (MDE) data by comparing observed network connections against known TyKit indicators of compromise (IOCs).

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the **Device Protect** Wortell MDR module.

### How to Detect?

The detection works by cross-referencing recent outbound network connections from endpoints with a list of known TyKit command-and-control (C2) domains. It retrieves these domains from an external threat intelligence CSV hosted on GitHub, then searches the **DeviceNetworkEvents** table for any successful connections (ActionType = "ConnectionSuccess") within the last 24 hours. If a device connects to any domain that matches the TyKit IOC list or to domains that fit a regex pattern mimicking fake Microsoft login pages (e.g., loginmicr*.cc) the query flags those events as potential indicators of TyKit malware communication or phishing activity. In essence, it detects TyKit-related network behavior by combining known threat intelligence (IOCs) with pattern-based domain matching in recent network logs. Related activities will be detected with the following KQL query:

### KQL

```kql
    let Tykit=externaldata(Domain:string)
    [h'https://raw.githubusercontent.com/SlimKQL/Hunting-Queries-Detection-Rules/refs/heads/main/IOC/TyKit.csv']
    with (format='csv', ignoreFirstRecord=true)
    | project Domain;
    DeviceNetworkEvents
    | where Timestamp > ago(1d)
    | where ActionType == "ConnectionSuccess"
    | where RemoteUrl has_any(Tykit) or RemoteUrl matches regex @"^loginmicr.?s*.*\.cc$"
```

## How to Investigate?

1. validate the destination domain
   - identify which TyKit IOC domain or regex pattern was matched  
   - confirm if the domain is newly registered or previously flagged  
   - check domain age, registrar, and hosting provider  

2. review connection behavior
   - determine how frequently the device connected to the domain  
   - check if the connections are periodic (beaconing) or burst-based  
   - note ports and protocols used  

3. analyze the initiating process
   - identify which process made the network connection  
   - review the full command line and execution path  
   - assess whether the process is legitimate or suspicious  

4. correlate with endpoint activity
   - look for file downloads or script execution after the connection  
   - check for new persistence mechanisms (scheduled tasks, registry keys)  
   - identify any credential access or discovery commands  

5. assess user context
   - determine which user was logged in during the activity  
   - check if the user has a history of similar events  
   - validate whether their role justifies the behavior  

6. scope across the environment
   - search for the same domain contacted by other devices  
   - identify common process names or command lines  
   - determine if activity aligns with a broader campaign
