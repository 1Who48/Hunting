## WSH-0022 HTTP Client Tools Exploitation For ATO Detection

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0022 HTTP Client Tools Exploitation For ATO Detection"_ has been created, how to use it.

### Required Access

## Overview

This custom detection query is designed to identify the creation of spoof directories that include Unicode characters in their names. Such directories are often used by attackers to bypass Endpoint Detection and Response (EDR) solutions.

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Identity Protect** module.

### How to Detect?

This query is designed to detect potential account takeover (ATO) attacks by identifying suspicious HTTP client tools being used. Here's a simplified breakdown of what the query does:

* Data Source: It pulls in a list of known suspicious HTTP client tools from an external source (a GitHub repository).
* Parsing: The raw data from this external source is parsed to extract indicators of compromise (IOCs), which are essentially identifiers for these suspicious tools.
* Filtering Events: The query then examines cloud application events that have occurred in the last hour.
* Detection: It filters these events to find any instances where the user agent or internet service provider (ISP) matches any of the known suspicious HTTP client tools from the list.

In essence, the query is looking for recent cloud application activities that involve known malicious HTTP client tools, which could indicate an attempt to exploit these tools for unauthorized account access.

### KQL

```kql
    let HTTPClientTools=externaldata(RawData:string)
    [h'https://raw.githubusercontent.com/SlimKQL/Hunting-Queries-Detection-Rules/refs/heads/main/IOC/Proofpoint_HTTPClientTools_ATO.txt']
    | parse RawData with IOC:string;
    let HTTPClientToolsIOC = HTTPClientTools | project IOC;
    CloudAppEvents
    | where Timestamp > ago(1d)
    | where UserAgent has_any(HTTPClientToolsIOC) and ISP has_any(HTTPClientToolsIOC)
```

## How to Investigate?

1. Identify the affected accounts
    * Review which users or service accounts generated the traffic and determine if their behavior aligns with normal job functions or automation.

2. Analyze the user agent strings
    * Compare the detected user agents to known legitimate tools versus suspicious or uncommon HTTP client utilities linked to credential abuse or automation.

3. Check authentication activity
    * Look for abnormal login patterns such as impossible travel, repeated failures, new locations, or logins outside normal working hours.

4. Review accessed resources
    * Determine what cloud applications, files, or APIs were accessed and assess whether any sensitive data was viewed or modified.

5. Correlate with other security logs
    * Check endpoint, identity, and network logs for malware alerts, suspicious processes, or signs of credential theft around the same timeframe.

6. Assess persistence and scope
    * Investigate if the activity is recurring, spreading to other accounts, or tied to automation scripts that may indicate account takeover or abuse.
