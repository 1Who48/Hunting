## WSH-0025 Detect rundll.exe being misused

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0025 Detect rundll.exe being misused"_ has been created, how to use it.

### Required Access

These hunting cases are linked through a published application that grants us permission to perform threat hunting via the API in our customers' security portals.

## Overview

Hunt on detect rundll.exe being used for reconnaissance and command-and-control

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

Detects activities of disabling for Microsoft Defender Antivirus and Microsoft Defender for Endpoint in the **"DeviceNetworkEvents"** table

### KQL

```kql
    DeviceNetworkEvents
    | where Timestamp > ago(1d)
    | where InitiatingProcessFileName =~ "rundll32.exe"
    // Empty command line
    | where InitiatingProcessCommandLine has "rundll32.exe" and InitiatingProcessCommandLine !contains " " 
    and InitiatingProcessCommandLine != "" 
    | summarize DestinationIPCount = dcount(RemoteIP), make_set(RemoteIP), make_set(RemoteUrl), 
    make_set(RemotePort) by InitiatingProcessCommandLine, DeviceId, bin(Timestamp, 5m)
```

## How to Investigate?

1. Validate legitimacy of rundll32 usage
    * Rundll32 normally executes with a DLL and exported function.
    * An empty or minimal command line is highly abnormal. Confirm whether this aligns with any known admin tools, legacy software, or scripts in your environment.

2. Inspect destination patterns
    * Review the number of unique IPs, URLs, and ports contacted in each 5-minute window.
    * Multiple destinations or uncommon ports may indicate scanning, beaconing, or C2 activity.

3. Correlate with process ancestry
    * Identify what launched rundll32 (parent process, user context, scheduled task, service).
    * Malicious loaders often spawn it from Office, PowerShell, wscript, or temp directories.

4. Check file integrity and location
    * Verify rundll32.exe path and signature (should be in System32/SysWOW64 and Microsoft-signed).
    * Look for renamed copies or execution from user-writable paths.

5. Look for follow-on activity
    * Hunt for DLL drops, registry run keys, scheduled tasks, or new services created shortly before or after the network activity.
