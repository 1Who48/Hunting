## WSH-0028 Zero-Day CVE-2025-21333 Privilege Escalation

## Overview

This KQL query identifies endpoints where the vulnerability CVE-2025-21333 may be exploited through the creation of new executable files and changes to process tokens. It specifically checks for:

* Hyper-V Enabled Endpoints: These endpoints are running Windows Sandbox Server (WindowsSandboxServer.exe).
* Vulnerable Endpoints: These endpoints have a known vulnerability tied to CVE-2025-21333.
* New Executable Creation: Detection of newly created .exe files on the system in a short detection window (last 1 day).

The query focuses on endpoints where CVE-2025-21333 is present, new executables are created, and suspicious process token modifications occur. These activities are commonly observed when attackers are exploiting a vulnerability for privilege escalation or malicious behavior.

### How to Detect?

* HyperVEnabledEndpoint: This part of the query identifies devices that are running WindowsSandboxServer.exe, which is an indicator of Hyper-V-enabled endpoints, indicating virtualized environments where attackers may try to exploit vulnerabilities
  * VulnerableEndpoint: This section filters the devices based on the CVE ID CVE-2025-21333, which corresponds to a security vulnerability that could potentially be exploited. The query uses this to detect systems with this specific vulnerability.

* (NewExePOCCreation) New Exe file Creation: Here, the query detects any new .exe files created within the last 24 hours. This is a sign of potentially malicious executable creation.

* DeviceEvents: This part checks for suspicious activity in the form of "ProcessPrimaryTokenModified" events, which indicate a modification to the process token. Such modifications often correlate with privilege escalation attempts or other malicious activities.

Finally, the hunt combines all these factors:

* It ensures that the event occurred on endpoints with Hyper-V enabled and CVE-2025-21333 vulnerabilities.

* It looks for any new executables created recently and correlates these with suspicious process token modifications, which are common indicators of exploitation.

### KQL

```kql
    let QueryPeriod = 30d;
    let DetectionPeriod = 1d;
    let HyperVEnabledEndpoint =
    DeviceProcessEvents
    | where Timestamp > ago(QueryPeriod)
    | where FileName == "WindowsSandboxServer.exe"
    | distinct DeviceId;
    let VulnerableEndpoint =
    DeviceTvmSoftwareVulnerabilities
    | where CveId == "CVE-2025-21333"
    | distinct DeviceId;
    let NewExePOCCreation =
    DeviceFileEvents
    | where Timestamp > ago(DetectionPeriod)
    | where ActionType == "FileCreated"
    | where FileName endswith ".exe"
    | distinct FileName;
    DeviceEvents
    | where Timestamp > ago(DetectionPeriod)
    | where ActionType == "ProcessPrimaryTokenModified"
    | where FileName has_any(NewExePOCCreation)
    | where DeviceId has_any(HyperVEnabledEndpoint) and DeviceId has_any(VulnerableEndpoint)
```

## How to Investigate?

1. validate device exposure
   - confirm the endpoint is both hyper-v enabled and vulnerable to CVE-2025-21333  
   - verify patch status and when the vulnerability was last assessed  
   - check if the device role makes sandbox or virtualization usage expected  

2. analyze the newly created executable
   - identify the file name, full path, and creation source  
   - determine whether the file was downloaded, dropped by a process, or extracted from an archive  
   - check digital signature and compile timestamp  

3. review token modification behavior
   - inspect how the primary token was modified (privilege escalation indicators)  
   - determine which user context the process escalated from and to  
   - check whether SYSTEM or high-privilege tokens were obtained  

4. reconstruct execution chain
   - identify the parent process that launched the new executable  
   - check if it originated from powershell, scripts, installers, or browsers  
   - review command-line arguments for exploit patterns  

5. correlate timeline of exploitation
   - compare timestamps between file creation and token modification  
   - look for rapid privilege escalation after file creation  
   - identify any precursor exploitation activity  

6. scope for additional exploitation
   - search for similar token modification events on other vulnerable devices  
   - look for repeat creation of similar executables  
   - identify whether this behavior appears automated or targeted
