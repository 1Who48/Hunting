## WSH-0035 LOLbins that refer to a remote IP in the commandline.

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0035 LOLbins that refer to a remote IP in the commandline."_ has been created, how to use it.

### Required Access

These hunting cases are linked through a published application that grants us permission to perform threat hunting via the API in our customers' security portals.

### Custom Changes

* known behavior and websites are excluded on this hunting kql.

## Overview

This query detects unusual LOLbins that refer to a remote IP in the commandline.

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

Check in the **"DeviceNetworkEvents"** if any of the LOLbins make connections to remote IPs.

## How to Investigate?

1. Validate the LOLBin and why it’s being used
   - Confirm which binary initiated the network connection (e.g., rundll32, regsvr32, mshta, certutil, bitsadmin)
   - Determine whether that LOLBin is expected on the device for legitimate admin/software tasks
   - Review whether the LOLBin is commonly abused for download/execute, proxying, or script execution

2. Review the command line for embedded IP intent
   - Inspect how the IP appears in the command line (argument, URL, connect target, encoded script, config)
   - Check for signs of staging (download paths, temp locations, suspicious file extensions)
   - Note any obfuscation patterns (base64, escape characters, unusual quoting)

3. Assess the destination and port behavior
   - Identify the external RemoteIP contacted and whether it is repeated across multiple events/devices
   - Evaluate the RemotePort usage for uncommon or high-risk patterns (non-standard ports, rapid switching)
   - Determine if RemoteUrl is empty (direct-to-IP) or present (domain-fronting / SNI mismatch possibilities)

4. Confirm parent-process legitimacy
   - Review the initiating process parent name and whether it makes sense for that LOLBin to be spawned
   - Pay special attention to unexpected parents (Office apps, browsers spawning script hosts, services spawning user tools)
   - Determine whether the activity aligns with interactive user behavior or background automation

5. Correlate with host activity around the same time
   - Look for nearby process events indicating download or execution (new binaries, scripts, scheduled tasks)
   - Check for file creation in user-writable paths (Temp, AppData, ProgramData) following the connection
   - Review any credential access, discovery commands, or persistence attempts shortly before/after

6. Scope for repeatability and campaign indicators
   - Check if the same command line pattern (same IP or same LOLBin usage) appears on other endpoints
   - Identify whether multiple devices contact the same RemoteIP (suggesting shared C2 or infrastructure)
   - Look for time clustering (bursts) that could indicate automated tooling rather than manual admin actions
