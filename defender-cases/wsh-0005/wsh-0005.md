## WSH-0005 Detecting LNK stomping

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0005 Detecting LNK stomping"_ has been created, how to use it.

### Required Access

These hunting cases are linked through a published application that grants us permission to perform threat hunting via the API in our customers' security portals.

### Custom Changes

* No custom changes are made.

## Overview

A bug in the handling of LNK files, can help threat actors bypass Smart App Control security controls designed to block untrusted applications. The below KQL should detect the behavioral signal of LNK stomping.

### MITRE ATT&CK

This attack tactic can be mapped on the MITRE ATT&CK framework:

| Tactic                | Techniques |
|-----------------------|------------|
|  Persistence          | T1547      |

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

The **"DeviceFileEvents"** we can hunt on the bug in the handling of LNK files, investigate threat actors bypass Smart App Control security controls designed to block untrusted applications.

### KQL

```kql
    DeviceFileEvents
    | where Timestamp > ago(1d)
    | where ActionType == "FileModified"
    | where FileName endswith ".lnk"
    | where InitiatingProcessFileName has "explorer.exe"
    | distinct DeviceName,FileName,FolderPath,InitiatingProcessAccountUpn
```

## How to Investigate?

Look for strange files that are created.

Such as; cmd.exe, powershell.exe, wscript.exe, mshta.exe, rundll32.exe, or regsvr32.exe. Unusual paths like AppData\Roaming, Temp, or a network shares. If investigation is needed this can be done in the security portal of the customer.

When in doubt download the file to your sandbox and follow this guide:

```powershell
#Calculate the hash of the LNK file Replace file with your downloaded file. Input hash in virustotal.
$lnkPath = ".\FILE.lnk"
$hash = Get-FileHash -Path $lnkPath -Algorithm SHA256
$hash

#Create a WScript.Shell COM object and access the shortcut to see what it does in text form to execute nothing.
$wshShell = New-Object -ComObject WScript.Shell
$shortcut = $wshShell.CreateShortcut($lnkPath)
$shortcut | Select *
```

The filehash can be submitted to virustotal.com to see if this is a known bad .lnk file.

Otherwise review the output from the Select * statement to see if any malicious or suspicious shortcuts have been made.

## How to respond?

If the incident is identified as true positive, proceed with standard remediation actions

### Custom Remediation Actions

If the device in question is a windows endpoint you can try to delete the file in question using a live response session.
Follow below steps to delete the file using live response:

1. Navigate to the device page
2. Start a live response session
3. Use the dir command to check if the life response is working:
    ```
    dir
    ````
4. Navigate to the folder where the malicious file resides:
    ```
    cd "C:\path\to\folder"
    ```
5. Confirm the file exists:
    ```
    dir filename.ext
    ```
6. Delete the file:
    ```
    del "C:\path\to\file\filename.ext"
    ```
    or force it if required:
    ```
    del /f "C:\path\to\file\filename.ext"
    ```
7. Verify that the file is deleted:
    ```
    dir "C:\path\to\file"
    ```
8. End the live response session.

### Standard Remediation Actions

If the file cannot be deleted or live response is not working the following standard remediation actions have to be executed in order to contain the threat:

* [ws-vrt-contain-device](../../../Usecases/remediation-actions/ws-vrt-contain-device.md)

If the file is successfuly deleted or the device is contained the following standard remediation actions have to be executed:
