## WSH-0047 Data Exfiltration via Microsoft Teams

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0047 Data Exfiltration via Microsoft Teams"_ has been created and how to use it.

### Required Access

These hunting cases are linked through a published application that grants us permission to perform threat hunting via the API in our customers' security portals.

### Custom Changes

## Overview

This usecase detects Teams message to an external domain upon the arrival of a new email.

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Identity Protect Cloud** module.

### How to Detect?

The **"CloudAppEvents"** table can be used to hunt for suspicious data exfiltration. Related activities will be detected with the following KQL query:

### KQL

```kql
    let timeframe = 20d; // Look at the last 30 days for context
    let real_time_window = 1h; // Real-time monitoring window
    let threshold = 3;
    let data =
    CloudAppEvents
    | where Application == "Microsoft Teams"
    | where ActionType == "MessageSent"
    | extend AccountUPN = RawEventData.UserId
    | extend CommsType = RawEventData.CommunicationType
    | extend ExternalTenant = RawEventData.ParticipantInfo.HasForeignTenantUsers
    | extend ExtUserDomain = tostring(split(AccountUPN, '@')[1])
    | where CommsType == "OneOnOne" or CommsType == "GroupChat"
    | where ExternalTenant == "true"
    | where ExtUserDomain != ""
    | summarize Count = count() by ExtUserDomain, bin(Timestamp, 1h) // Summarize data by hourly bins
    | where Timestamp > ago(timeframe);
    let rolling_stats =
    data
    | summarize RollingMean = avg(Count), RollingStdDev = stdev(Count) by ExtUserDomain;
    let real_time_data =
    data
    | where Timestamp > ago(real_time_window); // Focus on the real-time window
    real_time_data
    | join kind=inner (rolling_stats) on ExtUserDomain
    | extend ZScore = (Count - RollingMean) / RollingStdDev
    | where abs(ZScore) > threshold
    | project Timestamp, ExtUserDomain, Count, ZScore
    | order by Timestamp desc;
```

## How to Investigate?

1. review the anomalous domain activity
   - identify which external domains triggered the z-score alert
   - compare the current message volume to historical averages
   - determine if the spike is significantly above normal patterns

2. analyze message content and context
   - review sample messages sent to or from the external domain
   - check for phishing lures, malicious links, or social engineering language
   - identify whether the messages appear automated or templated

3. assess sender behavior
   - determine which internal users are communicating with the external domain
   - check if those users normally interact with external tenants
   - look for unusual login patterns tied to those accounts

4. evaluate recipient scope
   - identify how many external users were contacted
   - check if the same message was sent to multiple recipients
   - determine if group chats were created unexpectedly

5. correlate with other security signals
   - look for suspicious file shares, link clicks, or downloads in Teams
   - check for risky sign-ins associated with involved accounts
   - review any recent privilege or role changes

6. identify campaign indicators
   - check if multiple internal users are involved with the same external domain
   - look for time clustering suggesting scripted behavior
   - determine if similar spikes occurred previously
