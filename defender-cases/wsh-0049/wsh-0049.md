## WSH-0049 Dropping Payload via certutil

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0049 Dropping Payload via certutil"_ has been created, how to use it.

### Required Access

These hunting cases are linked through a published application that grants us permission to perform threat hunting via the API in our customers' security portals.

### Custom Changes

* No custom changes are made.

## Overview

This query Detecting is users are triggert to use the certutil to download web-content that attackers are using.

### MITRE ATT&CK

This attack tactic can be mapped on the MITRE ATT&CK framework:

| Tactic                | Techniques |
|-----------------------|------------|
| Initial Access        | T1566      |

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

The **"DeviceFileEvents"** we can hunt on strange activity based on the Tool certutil.exe.

### KQL

```kql
        DeviceFileEvents
        | where InitiatingProcessFileName !~ "certutil.exe"
        | where InitiatingProcessFileName !~ "cmd.exe"
        | where InitiatingProcessCommandLine has_all("-urlcache", "split", "http")
```

## How to Investigate?

1. review the initiating process
   - identify which binary executed the download activity
   - check if the process is a known application or an unusual executable
   - verify the file path to see if it runs from a user-writable or temp directory

2. analyze the command line intent
   - confirm how the -urlcache and split parameters are being used
   - determine what remote URL was accessed
   - check if the command resembles known file download or staging techniques

3. inspect the downloaded file
   - identify the file name, extension, and save location
   - check file hash reputation and digital signature
   - determine if the file was executed after download

4. correlate timing and behavior
   - review what occurred immediately before and after the file event
   - check for script execution, archive extraction, or process spawning
   - look for rapid chaining of download and execution

5. assess user and privilege context
   - determine which account initiated the activity
   - check if elevated privileges were used
   - validate whether the user normally performs command-line operations

6. scope across the environment
   - search for the same command pattern on other devices
   - identify repeated downloads from the same domain or IP
   - determine if this appears targeted or campaign-based
