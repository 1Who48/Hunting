## WSH-0014 Identify suspicious certificates

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0014 Identify suspicious certificates"_ has been created, how to use it.

### Required Access

These hunting cases are linked through a published application that grants us permission to perform threat hunting via the API in our customers' security portals.

### Custom Changes

* No custom changes are made.

## Overview

The following query leverages DeviceTvmCertificateInfo table which is available at the MDVM add-on license. Results provided include endpoints with certificates of zero keysize and no signature algorithm. A detected certificate lacks all the fundamental properties needed for secure communication and should be investigated.

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

The **"DeviceTvmCertificateInfo"** and **"DeviceInfo"** we can detected certificate lacks all the fundamental properties needed for secure communication and should be investigated.

### KQL

```kql
    let DeviceInformation = DeviceInfo
        | where Timestamp > ago(1d)
        | project Timestamp, DeviceId, DeviceName;
    DeviceInformation
    | join ( DeviceTvmCertificateInfo
        | where KeySize == "0"
        | where SignatureAlgorithm == ""
        | extend TOCN = parse_json(IssuedTo).CommonName
        | extend TOORG = parse_json(IssuedTo).Organization
        | extend TOCountry = parse_json(IssuedTo).CountryName 
        | extend BYCN = parse_json(IssuedBy).CommonName
        | extend BYORG = parse_json(IssuedBy).Organization
        | extend BYCountry = parse_json(IssuedBy).CountryName
        | project DeviceId, Thumbprint, TOCN, TOORG, TOCountry, BYCN, BYORG, BYCountry
    ) on DeviceId
    | project Timestamp, DeviceId, DeviceName, Thumbprint, TOCN, TOORG, TOCountry, BYCN, BYORG, BYCountry
```

## How to Investigate?

1. Validate certificate legitimacy
    * Review the certificate thumbprint and subject/issuer fields to determine whether the certificate is expected on the device.
    * Check whether the certificate belongs to internal PKI, third-party software, or an unknown/self-signed source.

2. Assess abnormal certificate properties
    * A key size of 0 and empty signature algorithm are highly unusual—investigate whether this indicates corruption, evasion, or abuse of a parsing weakness.
    * Determine if the certificate was recently installed, imported, or generated programmatically.

3. Evaluate usage and purpose
    * Identify what the certificate is being used for (TLS interception, code signing, authentication, persistence, or man-in-the-middle activity).
    * Check whether the certificate is bound to services, applications, or network listeners on the device.

4. Correlate with process and network activity
    * Review recent processes that interacted with certificate stores, especially installers, scripts, or unsigned binaries.
    * Look for outbound connections or local services using the suspicious certificate shortly after it appeared.

5. Assess scope and impact
    * Determine whether the same thumbprint or issuer appears across multiple devices, indicating automated deployment or lateral spread.
    * Evaluate whether affected devices handle sensitive data or privileged authentication.
