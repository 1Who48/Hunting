## WSH-0056 Suspicious Rundll32/Svchost Execution via LNK with Malicious Payload Indicators

## Overview

This detection looks for a fairly specific infection/execution pattern where a living-off-the-land Windows process (rundll32.exe or svchost.exe) is launched, but the launch can be traced back to a shortcut (.lnk) execution that referenced a document-like lure (e.g. a .pdf or even the string 申報物品清單 — “Declaration of Items List”).

* Why is that suspicious? Because in many phishing or initial-access cases:
* The user double-clicks a shortcut (.lnk) that pretends to be a document.
* That shortcut secretly calls a LOLBin (like rundll32.exe) to load or fetch a payload.
* The payload may be a .dll, .dat, .jpg, .zip, .png (sometimes a “non-PE” file is later decoded).
* The files or commands often live in user-writable locations like C:\Users\..., %AppData%, Temp, or are trying to blend in with C:\Windows\System32.

This query stitches those pieces together: a high-risk parent (a .lnk pretending to be a doc) → a LOLBin child (rundll32/svchost) → suspicious file types/paths. That’s a strong indicator of a staged or disguised execution chain, not normal user behavior.

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **DeviceProcessEvents** module.

### How to Detect?

This detection identifies a potential phishing or initial compromise chain where a malicious Windows shortcut (.lnk) file masquerading as a document triggers the execution of rundll32.exe or svchost.exe to load or execute suspicious payloads (e.g. .dll, .dat, .jpg, .zip, .png).

This activity often indicates the use of Living-Off-the-Land Binaries (LOLBins) to execute attacker-controlled code under the guise of legitimate Windows processes.

### KQL

```kql
    DeviceProcessEvents
    | where Timestamp > ago(2d)
    | where FileName in~ ("Rundll32.exe", "svchost.exe")
    | where (InitiatingProcessFileName endswith ".lnk" or InitiatingProcessCommandLine has ".lnk")
    | where InitiatingProcessCommandLine has_any (".pdf", ".申報物品清單") //Translates to "Declaration of Items List" 
    | where ProcessCommandLine has_any (".dll", ".dat", ".jpg", ".zip", ".png")
    | where FolderPath has_any (@"C:\Users", @"C:\Windows\System32", "Temp", "Appdata", "Public")
            or InitiatingProcessFolderPath  has_any (@"C:\Users", @"C:\Windows\System32", "Temp", "Appdata", "Public")
            or ProcessCommandLine has_any ("Document", "Temp", "Appdata", "Public")
    | project Timestamp, DeviceName, FileName, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, FolderPath
    | order by Timestamp desc
```

## How to Investigate?

1. review the lnk execution context  
   - confirm which shortcut file (.lnk) triggered the process  
   - inspect the shortcut target and arguments to see what it actually launches  
   - determine where the shortcut was located (email attachment, downloads, desktop, temp)

2. analyze the decoy file indicators  
   - review references to .pdf or the Chinese filename to identify the lure theme  
   - determine if the user recently opened a document with that name  
   - correlate with email, Teams, or browser download activity  

3. inspect rundll32 or svchost behavior  
   - analyze the full command line to see which DLL or payload was executed  
   - verify whether the file extension used (.dat, .jpg, .zip, .png) is masquerading as a DLL  
   - check if the execution path is unusual for legitimate system processes  

4. assess file locations and staging paths  
   - review whether payloads reside in user-writable or temp directories  
   - check if multiple suspicious files exist in the same folder  
   - determine if filenames mimic legitimate documents or images  

5. reconstruct execution timeline  
   - identify what happened immediately before the shortcut execution  
   - look for file creation or extraction events shortly prior  
   - check for additional processes spawned afterward  

6. scope for similar patterns  
   - search for the same shortcut name or payload across other devices  
   - identify repeat command-line patterns  
   - determine if multiple users received similar lure files
