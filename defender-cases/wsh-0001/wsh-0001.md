## WSH-0001 MSBuild.exe as a LOLBin to communicate with the C2

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why case _"WSH-0001 MSBuild.exe as a LOLBin to communicate with the C2"_ has been created, how to use it, how to investigate it, and what to do in case of true positive incidents.

### Required Access

These cases are linked through a published application that grants us permission to perform threat hunting via the API in our customer's security portals.

### Custom Changes

* No custom changes are made.

## Overview

When this case appears, it indicates that the legitimate Microsoft Build Engine (MSBuild.exe) is being exploited as a Living-off-the-Land Binary (LOLBin) to establish communication with a Command and Control (C2) server. This technique leverages trusted, signed binaries to evade detection by security tools.

### MITRE ATT&CK

This attack tactic can be mapped on the MITRE ATT&CK framework:

| Tactic | Techniques |
|--------|------------------|
| **Defense Evasion** | **T1127** Trusted Developer Utilities Proxy Execution |

## Applicability & Technical Requirements

This case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

Through the device activity, which is based on the **DeviceProcessEvents** table, we can hunt on strange activity regarding the MSBuild as LOLBin attack with the following KQL query.

### KQL

```kql
DeviceProcessEvents 
| where Timestamp > ago(3d)
| where InitiatingProcessFileName =~ "wmiprvse.exe" 
| where FileName =~ "msbuild.exe" and ProcessCommandLine has "programdata"
```

## How to Investigate?

To investigate this case:

* Verify the result through the security portal of the customer
* Locate the device and investigate the timeline or use the advanced hunting skill in the hunting notebook from Wortell.
