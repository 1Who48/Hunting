## WSH-0046 macOS ClickFix Attack with Base64 encrypted curl Command

## Document Classification

## Overview

This KQL rule identifies potential macOS ClickFix attacks, a technique where attackers use base64-encoded payloads executed via shell (e.g., bash or zsh), followed by a curl command to fetch additional malicious content. This sequence often indicates download-and-execute behavior, common in macOS exploitation and post-exploitation scripts. The rule filters out known safe commands to minimize false positives.

This rule helps identify early-stage macOS compromise attempts involving script-based payloads that decode and fetch remote malicious binaries, providing defenders with actionable context to investigate and contain threats.

### How to Detect?

#### Base64 Execution Detection

* Searches DeviceProcessEvents for processes launched by bash or zsh that contain "base64" in their command line that are not whitelisted. (e.g., MdeInstallerWrapper.py)
* These are stored as base64_events, marking the time, device, and user context.

#### Suspicious Curl Command Detection

* Looks for curl executions that are not whitelisted (e.g., Mozilla’s official download check).
* These are stored as curl_events.

#### Temporal Correlation (Within 10 Seconds)

* Joins base64_events and curl_events on matching device and user.
* Triggers when a curl command occurs within 10 seconds after a base64 command.
* Suggests that the base64-decoded output may have invoked a subsequent download action.

#### Network Confirmation

* Joins with DeviceNetworkEvents to confirm that the curl command successfully made a network connection (ActionType == "ConnectionSuccess") to the same domain extracted from the curl command.
* This step validates that the suspicious curl actually connected out, strengthening detection fidelity.

#### Output

* Displays timestamps, device, user, command lines, and extracted domains for analyst review.
* Sorting by the most recent base64 execution provides an immediate view of recent suspicious activity.

### KQL

```kql
   let WhitelistedCurlCLI = dynamic(["curl -fI https://download.mozilla.org/","jamfcloud.com","https://sofafeed.macadmins.io"]);
   let WhiteListedCommandLine = dynamic(["MdeInstallerWrapper.py"]);
   let base64_events = DeviceProcessEvents
   | where Timestamp > ago(1d)
   | where InitiatingProcessParentFileName in ("bash","zsh")
   | where ProcessCommandLine contains "base64"
   | where not(ProcessCommandLine has_any (WhiteListedCommandLine))
   | project Timestamp_base64 = Timestamp, DeviceName, AccountName, CommandLine_base64 = ProcessCommandLine;
   let curl_events = DeviceProcessEvents
   | where Timestamp > ago(1d)
   | where ProcessCommandLine contains "curl"
   | where not(ProcessCommandLine has_any (WhitelistedCurlCLI))
   | project Timestamp_curl = Timestamp, DeviceName, AccountName, CommandLine_curl = ProcessCommandLine;
   base64_events
   | join kind=inner (curl_events) on DeviceName, AccountName
   | where Timestamp_curl > Timestamp_base64 and Timestamp_curl <= Timestamp_base64 + 10s
   | project Timestamp_base64, Timestamp_curl, TimeDiff = Timestamp_curl - Timestamp_base64, DeviceName, AccountName, CommandLine_base64, CommandLine_curl
   | extend Domain = extract(@"https?://([^/]+)", 1, CommandLine_curl)
   | extend CurlUrl = extract(@"https?://[^\s]+", 0, CommandLine_curl)
   | sort by Timestamp_base64 desc
   | join kind=inner (
   DeviceNetworkEvents
   | where Timestamp > ago(1d)
   | where ActionType == "ConnectionSuccess"
   | project Timestamp = Timestamp, DeviceName, RemoteUrl, RemoteIP, RemotePort, ActionType, ReportId, DeviceId
   ) on DeviceName
   | where RemoteUrl contains Domain
   | where Timestamp >= Timestamp_curl
   | where Timestamp_curl > Timestamp_base64
```

## How to Investigate?

1. validate the sequence and intent
   - confirm base64 usage occurs immediately before curl (within seconds) as shown by the time difference
   - determine whether the base64 output is likely being used to build a URL, header, token, or payload for the curl command
   - review whether the pattern repeats multiple times on the same host/account

2. analyze the base64 command line
   - inspect what is being encoded/decoded (decode flags, input source, piping, files referenced)
   - look for indicators of obfuscation such as long strings, echo/printf pipes, or redirected output
   - check whether the base64 activity references credentials, API keys, or script content

3. analyze the curl command line and extracted destination
   - review the full curl options to identify download vs beaconing (output flags, silent mode, headers, POST data)
   - validate the extracted domain and full URL for legitimacy and expected business use
   - check for redirects, unusual paths, query strings, or user-agent spoofing

4. correlate to network evidence
   - confirm a successful connection to the same domain occurs after the curl execution
   - review remote IP, port, and frequency of connections to understand whether it’s a one-off fetch or repeated callbacks
   - check whether multiple domains resolve to the same remote IP across events (infrastructure reuse)

5. review execution context and origin
   - confirm the shell context (bash/zsh) and whether the commands were interactive or script-driven
   - identify the parent process chain that led to the shell session (remote session tooling, terminal app, automation agent)
   - review account activity around the time of execution for anomalies

6. look for follow-on activity on the device
   - check for file creation events that align with curl downloads (new scripts, binaries, archives)
   - correlate with subsequent execution of newly created files or suspicious persistence behaviors
   - look for additional encoded/obfuscated command patterns suggesting staged execution
