## WSH-0033 Tracking activities of Mimikatz command-line by devices

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0033 Tracking activities of Mimikatz command-line by devices"_ has been created, how to use it.

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

Detect activities in DeviceProcessEvents where either: (a) the process is **Mimikatz identified by file name or PE version metadata** — `FileName`, `ProcessVersionInfoOriginalFileName`, or `ProcessVersionInfoInternalFileName` equal to `mimikatz.exe`, or `ProcessVersionInfoFileDescription`/`ProcessVersionInfoProductName` containing `mimikatz` — regardless of command line; or (b) **PowerShell** (`powershell.exe`, `powershell_ise.exe`, `pwsh.exe`) is invoked with **Mimikatz module syntax** (`module::command`, such as `sekurlsa::`, `lsadump::`, `kerberos::`, `vault::`, `crypto::`, `privilege::`, `token::`, `misc::skeleton`) in the process or initiating process command line. Each match is tagged with a `DetectionReason` indicating which branch fired.

### KQL

```kql
   let MimikatzModules = dynamic(["sekurlsa::","kerberos::","crypto::","vault::","lsadump::","privilege::","token::","misc::skeleton"]);
   DeviceProcessEvents
   | where Timestamp > ago(1d)
   | extend DetectionReason = case(
      FileName =~ "mimikatz.exe" or ProcessVersionInfoOriginalFileName =~ "mimikatz.exe" or ProcessVersionInfoInternalFileName =~ "mimikatz.exe" or ProcessVersionInfoFileDescription has "mimikatz" or ProcessVersionInfoProductName has "mimikatz", "Mimikatz binary by name/metadata",
      FileName in~ ("powershell.exe","powershell_ise.exe","pwsh.exe") and (ProcessCommandLine has_any (MimikatzModules) or InitiatingProcessCommandLine has_any (MimikatzModules)), "Mimikatz module syntax in command line",	"")
   | where isnotempty(DetectionReason)
   | project DeviceName, DetectionReason, FileName, ProcessVersionInfoOriginalFileName, ProcessVersionInfoFileDescription, ProcessCommandLine, ProcessCreationTime, InitiatingProcessCommandLine, InitiatingProcessFileName, InitiatingProcessFolderPath
```

## How to Investigate?

1. Confirm the credential-access intent
   - Review the `DetectionReason` to see which branch fired: `Mimikatz binary by name/metadata` or `Mimikatz module syntax in command line`
   - For metadata hits, compare `FileName` against `ProcessVersionInfoOriginalFileName`/`ProcessVersionInfoFileDescription` — a mismatch indicates a renamed Mimikatz binary
   - For command-line hits, identify which module(s) triggered the match (e.g., `sekurlsa::`, `lsadump::`, `kerberos::`, `vault::`, `crypto::`)
   - Note whether the suspicious syntax appears in the child process command line, the initiating process command line, or both

2. Validate the context for benign use
   - Confirm the host is not a sanctioned penetration-testing or red-team system where Mimikatz use is authorized
   - Verify the host role and whether elevated/administrative activity is expected for that user and time
   - For metadata-only hits where the command line looks benign, confirm the binary is genuinely Mimikatz (hash/file lookup) and not a benign tool sharing version-resource strings

3. Reconstruct the process chain
   - Identify the initiating process file name, full command line, and folder path
   - Determine what launched PowerShell/Mimikatz (script host, scheduled task, service, remote execution tool, interactive session)
   - Look for suspicious parent locations (user-writable paths, temp directories, unusual program folders)

4. Assess the target and technique specifics
   - If `sekurlsa::` is present, treat it as likely memory credential access behavior (e.g., `sekurlsa::logonpasswords`)
   - If `lsadump::` is present, evaluate whether it suggests SAM/LSA secrets or DCSync extraction intent
   - If `kerberos::` is present, check for ticket-focused activity (Golden/Silver ticket, TGT/TGS handling, ticket export/import)

5. Correlate with privilege and logon activity
   - Check which user context executed the process and whether it had elevated privileges
   - Correlate timing with recent admin logons, privilege changes, or unusual interactive sessions on the same host
   - Identify whether the activity coincides with remote access (RDP/SMB/WinRM) into the device

6. Look for supporting artifacts and follow-on behavior
   - Check for related file creation (scripts, dumped outputs, archives) around the process creation time
   - Review nearby security events for LSASS access, credential dumping alerts, or suspicious handle access
   - Correlate with outbound network activity shortly after execution that could suggest staging or data collection
