## WSH-0008 Detect Spear Phishing using Copilot for Microsoft 365

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0008 Detect Spear Phishing using Copilot for Microsoft 365"_ has been created, how to use it.

### Required Access

These hunting cases are linked through a published application that grants us permission to perform threat hunting via the API in our customers' security portals.

### Custom Changes

* No custom changes are made.

## Overview

At #BHUSA, Zenity Labs CTO Michael Bargury showcased how a compromised Copilot user account can be leveraged for spear phishing attacks using the user’s profiling data. For detailed steps on conducting these attacks, refer to the article “Phishing is Dead, Long Live Spear Phishing.”

This attack tactic can be mapped on the MITRE ATT&CK framework:

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

The **"DeviceFileEvents"** we can hunt on strange activity based on file creation, Drive load event and Tampering attempt detection.

### KQL

```kql
    let UncommonCopilotPromptUpn =
    CloudAppEvents
    | where Timestamp > ago(1h)
    | where Application == @"Microsoft Copilot for Microsoft 365"
    | where ActionType == @"CopilotInteraction"
    | extend UserID = tostring(RawEventData.UserId)
    | extend CopilotData = todynamic(RawEventData.CopilotEventData)
    | extend CopilotAppHost = tostring(CopilotData.AppHost)
    | where CopilotAppHost == "bizchat"
    | where UncommonForUser has "ISP" or UncommonForUser has "CountryCode"
    | distinct UserID;
    EmailEvents
    | where SenderFromAddress has_any (UncommonCopilotPromptUpn)
    | where EmailDirection == "Outbound"
    | where AttachmentCount > 0 or UrlCount > 0

    // ** Version 2 - Improve detection on PowerPwn **

    let UncommonCopilotPromptUpn =
    CloudAppEvents
    | where Application == @"Microsoft Copilot for Microsoft 365"
    | where ActionType == @"CopilotInteraction"
    | extend UserID = tostring(RawEventData.UserId)
    | extend CopilotData = todynamic(RawEventData.CopilotEventData)
    | extend CopilotAppHost = tostring(CopilotData.AppHost)
    | where CopilotAppHost == "bizchat"
    | where UncommonForUser has "ISP" or UncommonForUser has "CountryCode"
    | distinct UserID;
    let PowerPwnUpn =
    AADSignInEventsBeta
    | where AccountUpn has_any (UncommonCopilotPromptUpn)
    | where ResourceDisplayName == "Office 365 Exchange Online"
    | where UserAgent contains "python"
    | distinct AccountUpn;
    EmailEvents
    | where SenderFromAddress has_any (PowerPwnUpn)
    | where EmailDirection == "Outbound"
    | where AttachmentCount > 0 or UrlCount > 0
```

## How to Investigate?

1. Validate the Copilot activity context
    * Review the user’s Copilot interaction timeline to confirm whether prompts originated from unusual locations, ISPs, or devices.
    * Check if the Copilot usage aligns with the user’s role, normal working hours, and historical behavior.

2. Assess account sign-in legitimacy
    * Investigate recent sign-ins for the identified users, paying close attention to automation indicators such as scripted or non-browser user agents.
    * Confirm whether the sign-ins originated from known corporate IP ranges or previously unseen infrastructure.

3. Analyze outbound email intent and content
    * Examine outbound emails sent by the flagged users for signs of data exfiltration, phishing, or mass distribution.
    * Inspect attachments and embedded URLs for sensitive data, abnormal file types, or links to newly registered or suspicious domains.

4. Check for privilege misuse or lateral movement
    * Determine whether the affected accounts hold elevated roles or delegated mailbox permissions that could amplify impact.
    * Look for signs of mailbox access, forwarding rule creation, or abuse of shared mailboxes.

5. Correlate with other security signals
    * Review alerts related to impossible travel, anomalous token usage, or unusual API access involving the same users.
    * Cross-check endpoint telemetry to see if automation tools or scripting environments were active on the user’s device.
