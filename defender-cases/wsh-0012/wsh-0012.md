## WSH-0012 Probable AdFind Recon Tool Usage

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0012 Probable AdFind Recon Tool Usage"_ has been created, how to use it.

### Required Access

These hunting cases are linked through a published application that grants us permission to perform threat hunting via the API in our customers' security portals.

### Custom Changes

* Known behavior and conformation from the customer are excluded from detection.

## Overview

This query searches Identifies the host and account that executed AdFind by hash and filename in addition to common and unique flags that are used by many threat actors in discovery.

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

The **"DeviceActivity"** based on the DeviceFileEvents we can hunt on strange activity based on IIS or Apache process.

### KQL

```kql
    let args = dynamic(["objectcategory","domainlist","dcmodes","adinfo","trustdmp","computers_pwdnotreqd","Domain Admins", "objectcategory=person", "objectcategory=computer", "objectcategory=*","dclist"]);
    let parentProcesses = dynamic(["pwsh.exe","powershell.exe","cmd.exe"]);
    let ProcessCommandLine_ = datatable(InitiatingProcessCommandLine:string)["Admin.bat","AdDhcpDumps.cmd"];
    let ProcessParentFileName_ = dynamic(["MSExchangeHMWorker.exe","bldeploy.exe"]);
    DeviceProcessEvents
    | where Timestamp > ago(1d)
    //looks for execution from a shell
    | where InitiatingProcessFileName in~ (parentProcesses)
    // main filter
    | where FileName =~ "AdFind.exe" or SHA256 == "c92c158d7c37fea795114fa6491fe5f145ad2f8c08776b18ae79db811e8e36a3"
        // AdFind common Flags to check for from various threat actor TTPs
        or ProcessCommandLine has_any (args)
    | extend HostName = split(DeviceName, '.', 0)[0], DnsDomain = strcat_array(array_slice(split(DeviceName, '.'), 1, -1), '.'), FileHashAlgorithm = "SHA256"
    | where not(InitiatingProcessCommandLine  has_any(ProcessCommandLine_))
    | where not(InitiatingProcessParentFileName has_any(ProcessParentFileName_))
```

## How to Investigate?

1. Confirm tool legitimacy and ownership
    * Determine whether AdFind was executed by an authorized administrator, security team, or automated management process.
    * Validate the binary’s location, hash, and compile metadata to ensure it is not a renamed or trojanized variant.

2. Analyze execution context
    * Review the parent shell process and command line to understand how AdFind was launched (interactive admin action vs. scripted attacker activity).
    * Pay attention to execution from generic shells, which often indicates hands-on-keyboard reconnaissance.

3. Assess reconnaissance intent
    * The arguments highlighted in this detection are commonly used to enumerate domain structure, trusts, users, computers, and privileged groups—evaluate which AD objects were targeted.
    * Determine whether the scope of enumeration exceeds the user’s normal administrative duties.

4. Review user privileges and access level
    * Identify whether the executing account is a domain admin or a standard user performing unexpected directory enumeration.
    * Investigate whether the account recently experienced credential exposure or abnormal sign-in behavior.

5. Correlate with follow-on activity
    * Look for subsequent actions such as Kerberos abuse, lateral movement attempts, password attacks, or privilege escalation shortly after AdFind execution.
    * Check for staging behavior like output redirection to files or compression utilities used to store results.
