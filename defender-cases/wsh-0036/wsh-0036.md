### How to Detect?

The **"DeviceActivity"** based on the DeviceFileEvents we can hunt on strange activity based on sessions cookies.

### KQL

```kql
    // E.g Approved Corporate RMM - Whitelisting
    let SanctionRMM = dynamic("bomgarcloud.com");
    // Lookup list of RMM Tools Url from Microsoft
    let RMMList=externaldata(URI: string, RMMTool: string)
    [h'https://raw.githubusercontent.com/jischell-msft/RemoteManagementMonitoringTools/refs/heads/main/Network%20Indicators/RMM_SummaryNetworkURI.csv'];
    let RMMUrl =
    RMMList
    | project URI;
    MessageUrlInfo
    | where Timestamp > ago(1d)
    // Scan all external inbound Teams message for RMM Tools URL
    // For example: Storm-1811 exploits RMM tools to drop Black Basta ransomware 
    | where Url has_any(RMMUrl)
    | where not (Url has_any(SanctionRMM))
    | join MessageEvents on TeamsMessageId
    | where IsExternalThread == "1"
    | where ThreadType == "chat"
    | where DeliveryLocation == "Teams"
```

## How to Investigate?

1. validate the external message context
   - confirm the sender domain and whether it is known or previously trusted
   - review conversation history to see how the RMM link was introduced
   - determine if the message content is socially engineered or business-related

2. analyze the RMM URL characteristics
   - identify which remote management tool the URL belongs to
   - check if the URL points to a download page, installer, or session portal
   - note if the link uses URL shorteners, redirects, or unusual subdomains

3. assess recipient behavior
   - verify whether the recipient clicked or interacted with the link
   - check for follow-up messages encouraging installation or access
   - determine if multiple users received the same message

4. correlate with endpoint activity
   - look for recent RMM tool installations on recipient devices
   - check for new services, scheduled tasks, or remote sessions
   - correlate timestamps between message delivery and device activity

5. identify campaign indicators
   - search for the same URL or sender across other Teams conversations
   - look for identical message templates or phrasing
   - determine if this aligns with known ransomware or intrusion campaigns

6. evaluate user intent and awareness
   - confirm whether the user expected remote support
   - review any tickets or business requests tied to the interaction
   - determine if this could be pretexting for unauthorized access
