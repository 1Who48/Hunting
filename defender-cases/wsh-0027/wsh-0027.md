## WSH-0027 File Backup Deletion Alerts

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0027 File Backup Deletion Alerts"_ has been created, how to use it.

### Required Access

These hunting cases are linked through a published application that grants us permission to perform threat hunting via the API in our customers' security portals.

### Custom Changes

* No custom changes are made.

## Overview

This query checks alerts related to file backup deletion and enriches with additional alert evidence information.

### MITRE ATT&CK

This attack tactic can be mapped on the MITRE ATT&CK framework:

| Tactic                | Techniques |
|-----------------------|------------|
|  Impact               | T1485      |

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

Detects activities of disabling for Microsoft Defender Antivirus and Microsoft Defender for Endpoint in the **"DeviceNetworkEvents"** table

### KQL

```kql
    AlertInfo
    | where Timestamp > ago(1d)
    | where Title == "File backups were deleted"
    | join AlertEvidence on $left.AlertId == $right.AlertId
```

## How to Investigate?

1. Confirm what backups were removed
    * Identify which backup types were deleted (shadow copies, system state, catalogs, third-party backup files) and which volumes or repositories were affected.

2. Determine how deletion occurred
    * Review the evidence to see what tool or command performed the action (vssadmin, wbadmin, wmic, PowerShell, backup agent) and whether it was manual, scripted, or remote.

3. Identify the actor and access level
    * Check which user or service account initiated the activity and whether it had local admin or domain privileges.
    * Privileged misuse strongly increases risk.

4. Assess broader impact
    * Validate whether other devices show similar alerts and whether backup deletion is part of a wider pattern (log clearing, service stopping, shadow copy tampering).

5. Check for follow-on activity
    * Look for file encryption, mass file changes, ransom notes, credential theft, or outbound C2 traffic after the backup deletion event.
