## WSH-0038 Cookie Bite: Cloud Session Hijacking

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0038 Cookie Bite: Cloud Session Hijacking"_ has been created, and how to use it.

### Required Access

These hunting cases are linked through a published application that grants us permission to perform threat hunting via the API in our customers' security portals.

### Custom Changes

## Overview

This detection case targets a scenario where stolen authentication cookies are used by attackers to hijack cloud sessions, bypassing MFA and maintaining unauthorized access. The attackers exploit browser vulnerabilities, leveraging extensions to steal cookies and gain persistent access to cloud environments, without triggering MFA.

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

The **"DeviceFileEvents"** and **"DeviceProcessEvents"** tables are queried. This KQL detects potential attacks related to session hijacking by identifying PowerShell executions that load malicious browser extensions designed to steal session cookies.

* Identify New Browser Extensions: The query identifies newly created `.crx` files, which are commonly used for malicious browser extensions.
* Identify PowerShell Commands: The query checks for PowerShell processes used to load extensions that may exploit these stolen cookies.
* Correlate Devices: It correlates devices that have both the malicious extensions and PowerShell activity to flag potential hijacking attempts.

### KQL

```kql
let days_ago = ago(1d);
let EPwithNewExt =
    DeviceFileEvents
    | where ActionType == "FileCreated"
    | where FileName endswith ".crx"
    | distinct DeviceName;
DeviceProcessEvents
    | where Timestamp > (days_ago)
    | where (FileName =~ "powershell.exe" or InitiatingProcessFileName =~ "powershell.exe")
    | where ProcessCommandLine has_any ("load-extension")
    | where DeviceName in (EPwithNewExt)
```

### How to Investigate?

1. review the created browser extension
   - identify the extension file name and full path
   - check whether the extension is signed or from a trusted source
   - determine if the extension matches any known legitimate business tools

2. analyze the powershell command usage
   - review the full command line to understand how load-extension was used
   - identify whether the extension was loaded silently or via script automation
   - look for encoded or obfuscated parameters

3. confirm user context
   - determine which user account executed powershell
   - verify whether the user normally installs browser extensions
   - check for elevation or unusual privilege usage

4. correlate timeline of events
   - compare the timestamp of the .crx file creation with powershell execution
   - identify any preceding download activity
   - check for follow-on actions such as browser launches

5. inspect extension behavior
   - review extension permissions and requested access
   - check if it interacts with credentials, cookies, or browsing sessions
   - identify external domains contacted by the extension

6. scope environment impact
   - search for the same extension file across other devices
   - check if similar powershell commands appear elsewhere
   - determine if this activity is isolated or widespread
