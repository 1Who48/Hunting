## Overview

A recently discovered critical vulnerability in a widely used open-source web server software is being actively exploited. The flaw, affecting multiple versions, allows attackers to potentially execute arbitrary code under specific, non-default conditions. Initial exploit attempts were reported after a proof-of-concept was shared online.

Early attacks have been observed from a few IP addresses, mostly targeting servers in the U.S. and several other countries. However, security experts note that successful exploitation requires uncommon configurations, including enabling certain file upload methods and understanding the server’s internal structure.

### How to Detect?

The **"DeviceInfo"**,**"DeviceProcessEvents"** and **"DeviceNetworkEvents"** tables are queried. This KQL identifies internet-facing Tomcat servers that have interacted with known malicious IPs.

* Define Malicious IPs: A list of known attacker IPs is stored (GreyNoiseMaliciousIPs).
* Identify Internet-Facing Devices: Filters devices with a public IP (IsInternetFacing == true).
* Find Public-Facing Tomcat Instances: Detects Tomcat processes running in the last 24 hours on internet-facing devices.
* Track Network Activity: Monitors network events in the last 24 hours, checking if any Tomcat servers communicated with the malicious IPs.
* Flag Potential Attacks: If a match is found, it signals possible exploitation attempts.

### KQL

```kql
    let GreyNoiseMaliciousIPs = dynamic(["176.65.138.172","38.126.114.186",
    "188.213.161.98","140.143.182.115","196.240.54.120"]);
    let InternetFacing =
    DeviceInfo
    | where IsInternetFacing == true and isnotempty(PublicIP)
    | distinct DeviceId;
    let PublicFacingTomcatInstances =
    DeviceProcessEvents
    | where Timestamp > ago(1d)
    | where InitiatingProcessFileName has "tomcat"
    | summarize arg_max(TimeGenerated, *) by DeviceId
    | where DeviceId has_any(InternetFacing)
    | project DeviceId;
    DeviceNetworkEvents
    | where Timestamp > ago(1d)
    | where DeviceId has_any(PublicFacingTomcatInstances)
    | where RemoteIP has_any(GreyNoiseMaliciousIPs)
```

## How to Investigate?

1. validate the exposed tomcat instance
   - confirm the device is truly internet-facing and verify its public IP
   - identify which tomcat service or application is running
   - review the tomcat version for known vulnerabilities

2. review the malicious IP interaction
   - identify which GreyNoise IP was contacted and how often
   - determine if the connection was inbound, outbound, or bidirectional
   - check destination ports and protocols used

3. analyze request patterns
   - look for repeated connection attempts or scanning behavior
   - check for unusual HTTP methods or malformed requests
   - correlate timestamps with known exploit campaigns

4. inspect tomcat logs
   - review access logs for suspicious URIs or payloads
   - look for webshell indicators or unauthorized uploads
   - check error logs for exploit attempts or stack traces

5. correlate with host activity
   - look for new processes spawned by tomcat
   - check for file creation in web directories or temp paths
   - identify privilege escalation attempts

6. scope potential compromise
   - check if other internet-facing services show similar activity
   - search for the same malicious IPs across the environment
   - determine if multiple devices were targeted
