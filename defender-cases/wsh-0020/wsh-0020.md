## WSH-0020 Creation Of Spoof Directories With Unicode Characters

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0020 Creation Of Spoof Directories With Unicode Characters"_ has been created, how to use it.

### Required Access

These hunting cases are linked through a published application that grants us permission to perform threat hunting via the API in our customers' security portals.

### Custom Changes

## Overview

This custom detection query is designed to identify the creation of spoof directories that include Unicode characters in their names. Such directories are often used by attackers to bypass Endpoint Detection and Response (EDR) solutions.

### How to Detect?

This KQL query is designed to detect potentially malicious activities involving the creation of directories with spoofed names using Unicode whitespace characters. Here's a simplified breakdown of what the query does:

* Define Unicode Whitespace Characters: It sets up a list of Unicode whitespace characters that might be used to disguise directory names.
* Identify Suspicious Processes: It specifies a list of processes that are considered suspicious, such as powershell.exe, cmd.exe, and others commonly used in scripting or command execution.
* Filter Device File Events: The query looks at events related to file operations on devices.
* Exclude System-Level Processes: It filters out events initiated by the "SYSTEM" account, focusing on user-level activities.
* Check for Suspicious Processes: It further filters the events to only include those initiated by the suspicious processes listed earlier.
* Detect Unicode Whitespace in Folder Paths: It checks if any folder paths contain the defined Unicode whitespace characters, which could indicate an attempt to disguise the directory name.
* Extract Account Information: It splits the account name to separate the domain and the user name for further analysis.
* Exclude NT AUTHORITY Domain: It filters out events associated with the "NT AUTHORITY" domain to focus on user accounts.
* Select and Order Relevant Information: Finally, it selects specific fields like the timestamp, device name, account information, folder path, and command line used by the initiating process, and orders the results by timestamp for easier analysis.

This query helps in identifying potential security threats by spotting unusual directory creation activities that might be used to bypass security measures.

### KQL

```kql
    // Custom detection for the creation of spoof directories with Unicode characters
    let unicodeWhitespace = dynamic(["\u2000", "\u2001", "\u2002", "\u2003", "\u2004", "\u2005", "\u2006", "\u2007", "\u2008", "\u2009", "\u200A"]);
    let suspiciousProcesses = dynamic(["powershell.exe", "cmd.exe", "mshta.exe", "wscript.exe", "cscript.exe"]);
    DeviceFileEvents
    | where Timestamp >= ago(1d)
    // Exclude system-level processes
    | where InitiatingProcessAccountName != "SYSTEM"
    // Filter for known suspicious processes
    | where InitiatingProcessFileName in (suspiciousProcesses)
    | where FolderPath has_any (unicodeWhitespace)
    | extend AccountDomain = tostring(split(InitiatingProcessAccountName, "\\")[0]), AccountName = tostring(split(InitiatingProcessAccountName, "\\")[1])
    // Exclude NT AUTHORITY domain
    | where AccountDomain != "NT AUTHORITY"
    | project Timestamp, DeviceName, InitiatingProcessAccountName, InitiatingProcessAccountUpn, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine
    | order by Timestamp
```

## How to Investigate?

1. Validate the directory name visually and technically
    * Inspect the folder path using tools that reveal hidden Unicode characters to confirm the presence of zero-width or non-standard whitespace.
    * Determine whether the directory visually impersonates a trusted path or application folder.

2. Assess user intent and execution context
    * Review which user account created or interacted with the directory and whether this aligns with their role.
    * Execution via scripting engines or command shells strongly suggests intentional manipulation rather than accidental creation.

3. Inspect contents of the spoofed directory
    * Examine files stored within the directory for malicious scripts, droppers, or payloads designed to blend in with legitimate software.
    * Look for renamed binaries or files intended to masquerade as trusted executables.

4. Correlate with follow-on execution
    * Determine whether binaries or scripts from the spoofed directory were later executed.
    * Check for persistence mechanisms pointing to the Unicode path, such as startup entries or scheduled tasks.

5. Evaluate scope and reuse
    * Identify whether similar Unicode-based paths appear on other devices or were created by the same user.
    * Assess whether this technique is part of a broader campaign or isolated experimentation.
