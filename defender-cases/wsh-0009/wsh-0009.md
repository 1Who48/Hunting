## WSH-0009 Detecting FIDO2 Passkey Abuse

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0009 Detecting FIDO2 Passkey Abuse"_ has been created, how to use it.

### Required Access

These hunting cases are linked through a published application that grants us permission to perform threat hunting via the API in our customers' security portals.

### Custom Changes

* No custom changes are made.

## Overview

This detection identifies when a highly privileged user (e.g., Global Administrator) attempts to register a FIDO2 security key in Azure AD. While FIDO2 keys are a secure authentication method, unauthorized registrations could indicate account compromise or persistence tactics by an attacker.

### MITRE ATT&CK

This attack tactic can be mapped on the MITRE ATT&CK framework:

| Tactic                | Techniques |
|-----------------------|------------|
| Credential Access     | T1556.006  |

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

* Monitor Azure AD Sign In logs for FIDO2 authentication method registration requests.
* Filter for successful requests (ResponseStatusCode == 200).
* Validate the user session at the time of the request to confirm if it's legitimate or suspicious.

### KQL

```kql
let AbusedRoleMonitor = dynamic(["Privileged Role Administrator", "Global Administrator"]);
let FIDOAccountObjID =
MicrosoftGraphActivityLogs
| where TimeGenerated > ago(1d)
| where RequestUri has "/authentication/fido2Methods/creationOptions"
| where RequestMethod == "GET" and ResponseStatusCode == 200
| parse RequestUri with "https://graph.microsoft.com/beta/users/" 
UserObjectID "/authentication/fido2Methods/creationOptions"
| distinct UserObjectID;
IdentityInfo
| where TimeGenerated > ago(1d)
| where AccountObjectId has_any(FIDOAccountObjID)
| summarize arg_max(TimeGenerated, *) by AccountObjectId
| where AssignedRoles has_any(AbusedRoleMonitor)
```

## How to Investigate?

1. Verify User Activity:
    * Check if the FIDO2 registration attempt was expected (e.g., initiated by the user or IT team).
    * Is the user priveledge expected?
    * Review recent sign-ins for the user, including IP address, device, and location.

2. Check Session Validity:
    * Was the user logged in at the time of the request?
    * Was the session from a trusted or known IP?

3. Investigate for Anomalies:
    * Look for unusual login locations or new devices.
    * Check if other authentication methods were changed recently.

4. Contain and Respond (if suspicious):
    * Reset credentials and remove unauthorized FIDO2 keys.
    * Force a sign-out from all sessions.
