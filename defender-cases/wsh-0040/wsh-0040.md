## WSH-0040 Possible client side Bloodhound reconnaissance activities

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0040 Possible client side Bloodhound reconnaissance activities"_ has been created and how to use it.

### Required Access

These hunting cases are linked through a published application that grants us permission to perform threat hunting via the API in our customers' security portals.

### Custom Changes

* No custom changes are made.

## Overview

This usecase searches for LDAP queries that look like [Bloodhound/Sharphound](https://github.com/BloodHoundAD/BloodHound) and/or [AD Explorer](https://learn.microsoft.com/en-us/sysinternals/downloads/adexplorer) reconnaissance activities from client devices that are onboarded in Microsoft Defender for Endpoint.

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the **Identity Protect Cloud**, **Identity Protect On-premises**, **Device Protect** or **Azure Server protect** Wortell MDR modules.

### How to Detect?

The **"DeviceEvents"** table can be used to hunt for suspicious activities related to Bloodhound, Sharphound and/or AD Explorer related activities with the following KQL query:

### KQL

```kql
   let days_ago = ago(1d);
   let possible_malicious_payloads=dynamic(["objectGUID=*","(schemaIDGUID=*)","(&(objectclass=computer)(userAccountControl:1.2.840.113556.1.4.803:=8192))","(|(samAccountType=805306368)(samAccountType=805306369)(objectclass=organizationalUnit))","(|(samaccounttype=268435456)(samaccounttype=268435457)(samaccounttype=536870912)(samaccounttype=536870913))","(samAccountType=805306368)(samAccountType=805306369)"]);
   let WhiteListedCommandLine = dynamic([
      "QVDirectoryServiceConnector.exe",
      "microsoft.tri.sensor.exe",
      "citrix.cloudservices.agent.exe",
      '"Repository.exe" -iscentral -floatingcentral'
   ]);
   DeviceEvents
   | where Timestamp > days_ago
   | where ActionType =~ "LdapSearch"
   | where not(InitiatingProcessCommandLine has_any (WhiteListedCommandLine))
   | extend AdditionalFields_=parse_json(AdditionalFields)
   | extend SearchFilter_=tostring(AdditionalFields_.SearchFilter)
   | where SearchFilter_ has_any(possible_malicious_payloads)
   | project Timestamp, DeviceName, InitiatingProcessAccountUpn, InitiatingProcessFolderPath, InitiatingProcessVersionInfoOriginalFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, SearchFilter_
   | sort by Timestamp desc
```

## How to Investigate?

1. validate the ldap search intent
   - review the search filter used and identify which bloodhound or ad enumeration pattern it matches
   - determine what objects were targeted (computers, users, domain controllers, OUs, schema objects)
   - assess whether the query scope suggests reconnaissance or legitimate admin activity

2. analyze the initiating process
   - review the process name and original file name for legitimacy
   - check the folder path to see if it runs from a standard program directory or user-writable location
   - confirm it is not part of approved identity or monitoring tools

3. review parent process relationship
   - identify what launched the ldap search process
   - look for suspicious parents such as powershell, cmd, wscript, or remote tools
   - determine whether execution appears interactive, scripted, or automated

4. assess user context
   - check which account performed the ldap queries
   - validate if the account normally performs directory queries
   - look for recent privilege changes or abnormal logon behavior

5. correlate with other reconnaissance activity
   - search for additional ldap searches from the same device or account
   - check for net, nltest, dsquery, or ad-related command usage
   - look for bloodhound collection artifacts or output files

6. scope the activity
   - determine if other endpoints show similar ldap search patterns
   - identify if the same process or command line appears elsewhere
   - assess whether this is isolated or part of a broader enumeration campaign
