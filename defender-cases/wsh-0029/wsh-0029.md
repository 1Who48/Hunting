## WSH-0029 Detect DoppelPaymer operators dumping credentials with ProcDump

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0029 Detect DoppelPaymer operators dumping credentials with ProcDump"_ has been created, how to use it.

### Required Access

These hunting cases are linked through a published application that grants us permission to perform threat hunting via the API in our customers' security portals.

### Custom Changes

* No custom changes are made.

## Overview

DoppelPaymer is ransomware that is spread manually by human operators. These operators have exhibited extensive knowledge of system administration and common network security misconfigurations.throughout an organization.

### MITRE ATT&CK

This attack tactic can be mapped on the MITRE ATT&CK framework:

| Tactic                | Techniques |
|-----------------------|------------|
|  Credential Access    | T1555      |

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

Detects activities of disabling for Microsoft Defender Antivirus and Microsoft Defender for Endpoint in the **"DeviceNetworkEvents"** table

### KQL

```kql
    // Dumping of LSASS memory using procdump
    DeviceProcessEvents
    | where Timestamp > ago(1d)
    // Command lines that include "lsass" and -accepteula or -ma flags used in procdump
    | where (ProcessCommandLine has "lsass" and (ProcessCommandLine has "-accepteula" or
    ProcessCommandLine contains "-ma"))
    // Omits possible FPs where the full command is just "procdump.exe lsass" 
    or (FileName in~ ('procdump.exe','procdump64.exe') and ProcessCommandLine has 'lsass')
```

## How to Investigate?

1. Confirm the dump actually occurred
    * Identify whether an LSASS dump file was successfully created, its file path, size, and timestamp.
    * Any successful dump should be treated as credential compromise.

2. Identify the executing account
    * Check which user or service account ran the command and whether it had local admin or SYSTEM privileges.
    * Unauthorized admin usage is highly suspicious.

3. Analyze the process lineage
    * Determine what launched procdump (parent process, command origin).
    * Look for execution from PowerShell, cmd, scheduled tasks, remote tools, or malicious scripts.

4. Search for credential abuse
    * After the dump, investigate for lateral movement, abnormal authentication attempts, new sessions, or access to sensitive systems that could indicate stolen credentials being used.

5. Check for exfiltration activity
    * Look for network transfers, archive creation, or cloud uploads around the same time that could indicate the dump file was stolen.
