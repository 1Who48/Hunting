## WSH-0018 Remote File Creation with PsExec

## Document Classification

## Overview

This query detects remote file creation events that might indicate an active attack using PsExec

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

The **"DeviceFileEvents"** we can hunt on strange activity based on the Tool PsExec.

### KQL

```kql
    DeviceFileEvents
        | where Timestamp > ago(7d)
        | where InitiatingProcessCommandLine has "accepteula"
        | where FolderPath has "\\\\" and FileName endswith ".exe"
        | extend Exe = countof(InitiatingProcessCommandLine, ".exe")
        | where InitiatingProcessCommandLine !has ".ps1" and Exe > 1 or  InitiatingProcessCommandLine has 
         ".bat"
        | where not(InitiatingProcessCommandLine has_any("batch", "auditpol", "script", "scripts", 
          "illusive", "rebootrequired"))
        | summarize FileCount = dcount(FolderPath), make_set(SHA1, 100000), make_set(FolderPath, 
         100000),make_set(FileName, 100000), make_set(InitiatingProcessCommandLine, 100000) by DeviceId, 
          InitiatingProcessFileName
        | where FileCount > 4
```

## How to Investigate?

1. Validate the execution source
  * Confirm whether the executables were legitimately run from a network share or if the UNC path is unexpected for the device or user.
  * Identify the hosting server and share permissions to determine whether the location is trusted or potentially attacker-controlled.

2. Assess EULA-bypass behavior
  * The presence of accepteula indicates automated or scripted execution—review whether this aligns with sanctioned administrative tooling.
  * Determine whether the tools resemble Sysinternals utilities or renamed binaries often abused for reconnaissance or lateral movement.

3. Analyze execution chaining
  * Multiple .exe references and batch execution patterns suggest command chaining—review command lines for staging, enumeration, or remote execution logic.
  * Check whether the same process executed several binaries across different network paths in a short time frame.

4. Inspect the binaries
  * Review hashes, file names, and metadata to confirm whether the executables are known tools, custom malware, or modified legitimate utilities.
  * Pay attention to unsigned binaries or tools executed under misleading names.

5. Evaluate lateral movement indicators
  * Determine whether the activity coincides with credential usage, remote service creation, scheduled tasks, or access to multiple hosts.
  * Look for signs that the UNC-hosted executables were used to pivot or propagate across the environment.
