## WSH-0011 Possible webshell drop

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0011 Possible webshell drop"_ has been created, how to use it.

### Required Access

These hunting cases are linked through a published application that grants us permission to perform threat hunting via the API in our customers' security portals.

### Custom Changes

* Customer known path's are excluded for this detection.

## Overview

This query searches for files with common web page content extensions created by IIS or Apache that could run arbitrary code. It includes a throttling mechanism to reduce false positive detections for web-based content management.

### MITRE ATT&CK

This attack tactic can be mapped on the MITRE ATT&CK framework:

| Tactic                | Techniques |
|-----------------------|------------|
| Initial Access        | T1011      |
| Persistence           | T1053      |

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

The **"DeviceActivity"** based on the DeviceFileEvents we can hunt on strange activity based on IIS or Apache process.

### KQL

```kql
    let knownProcess_ = datatable(domainNames:string)["iisipm07470ea9-5ce9-4f7f-ba35-b0f4a6f5baa5","iisipm9b9360e4-c39b-41d5-afbb-578db7173c99","iisipm9d25ea7d-9b23-496c-a9e0-004e332b3ad9","iisipm2102a60e-d93d-4cb6-beda-f7b8760c8b06","iisipmee2e8648-ba72-4cdf-9992-1d9d3550d9c0","iisipmad550395-46f1-46ab-92dd-e08ea8ac1341","iisipm4beb0580-2175-4153-aedd-d258a684d309","iisipm55090709-cd56-47e3-8902-e188c7d7530f","iisipmc6540152-2ab8-402c-9ce0-b8c0fbd5b4c9","iisipm3af9cc82-b79d-4c61-b08a-05cf4e6beb1f","iisipmb17224b0-03c9-4dbe-b460-7f20fc1a65de"];
    let MaxFileOperations = 3; // This will attempt to hide WebDAV publish operations by looking for file operations less than 'x' in a 5 minute period
    let MaxAge = ago(1d); // This is how far back the query will search
    let ExtensionList = pack_array('asp', 'aspx', 'aar', 'ascx', 'ashx', 'asmx', 'c', 'cfm', 'cgi', 'jsp', 'jspx', 'php', 'pl');//,'exe','dll','js','jar','py','ps1','psm1','cmd','psd1','java','wsf','vbs') Commented ones may cause false positive detection - add at will
    let IncludeTemp = false; // whether to include files that contain \temp\ in their path
    let PossibleShells = DeviceFileEvents 
    | where Timestamp > ago(1d)
        | where Timestamp > MaxAge and InitiatingProcessFileName in~('w3wp.exe', 'httpd.exe') and (IncludeTemp or FolderPath !contains @'\temp\') and ActionType in ('FileCreated', 'FileRenamed', 'FileModified')
        | extend extension = tolower(tostring(split(FileName, '.')[-1])),TimeBin = bin(Timestamp, 5m)
        | where extension in (ExtensionList);
    PossibleShells
    | summarize count() by DeviceId, TimeBin
    | where MaxFileOperations == -1 or count_ < MaxFileOperations
    | join kind=rightsemi PossibleShells on DeviceId, TimeBin
    | where not(InitiatingProcessCommandLine has_any(knownProcess_))
```

## How to Investigate?

1. Validate the affected web server context
    * Confirm the device is a legitimate web server and identify the hosted applications, frameworks, and expected file types.
    * Determine whether recent deployments, patches, or content updates could explain file changes made by the web service process.

2. Inspect the created or modified files
    * Review the filenames, extensions, and directories for indicators of web shells, such as short or random names, double extensions, or placement in web-accessible paths.
    * Examine file contents for obfuscation, encoded payloads, command execution logic, or backdoor functionality.

3. Analyze the creation pattern
    * This detection highlights low-volume file operations in short time windows—evaluate whether the activity aligns with attacker behavior attempting to evade thresholds.
    * Correlate timestamps with inbound HTTP requests, POST uploads, or exploitation attempts against the web application.

4. Review process and execution lineage
    * Investigate the command line and parent process of the web worker (w3wp.exe or httpd.exe) to identify unexpected modules, handlers, or script engines being invoked.
    * Look for subsequent execution of the created files or child processes spawned by the web service.

5. Assess attacker access and persistence
    * Determine whether the suspected web shell was accessed remotely after creation by reviewing inbound connections and command execution activity.
    * Check for persistence mechanisms such as scheduled tasks, startup scripts, or additional backdoors dropped on the server.
