## WSH-0060 ClawdBot VS Code Extension Dropping ScreenConnect RAT

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0060 ClawdBot VS Code Extension Dropping ScreenConnect RAT"_ has been created, how to use it.

### Required Access

These hunting cases are linked through a published application that grants us permission to perform threat hunting via the API in our customers' security portals.

### Custom Changes

* No custom changes are made.

## Overview

a malicious Visual Studio Code extension called “ClawdBot Agent” that was flagged by Aikido’s detection system on January 27, 2026. Although it appears to be a legitimate AI coding assistant, the extension silently drops a remote access trojan by installing a weaponized ScreenConnect client that automatically connects back to attacker infrastructure, giving persistent remote control to the threat actors. The real Clawdbot team never published this extension, and attackers used the trusted VS Code marketplace to distribute it while hiding its covert payload delivery.

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **DeviceProcessEvents**, **DeviceFileEvents** and **DeviceNetworkEvents** module.

### How to Detect?

This rule detects various activities associated with the ClawdBot campaign, which uses a fake VS Code extension to drop the ScreenConnect RAT. Detection logic includes suspicious network activity fetching malicious payloads (config.json, lightshot files, zoomupdate.msi) from known malicious domains or Dropbox, identification of known malicious file hashes, outbound connections to ScreenConnect C2 servers on port 8041, creation or start of ScreenConnect services, file dropping/staging in temporary directories, and execution of Code.exe or ScreenConnect binaries from temporary paths.

### KQL

```kql
   let maliciousHashes = dynamic([
      "adbcdb613c04fd51936cb0863d2417604db0cd04792ab7cae02526d48944c77b", // extension.js
      "04ef48b104d6ebd05ad70f6685ade26c1905495456f52dfe0fb42f550bd43388", // run.bat
      "e20b920c7af988aa215c95bbaa365d005dd673544ab7e3577b60fecf11dcdea2", // Code.exe (ScreenConnect)
      "d1e0c26774cb8beabaf64f119652719f673fb530368d5b2166178191ad5fcbea"  // DWrite.dll (Rust loader)
      ]);
   let maliciousDomains = dynamic(["meeting.bulletmailer.net","clawdbot.getintwopc.site","getintwopc.site","darkgptprivate.com"]);
   let maliciousIPs = dynamic(["179.43.176.32","178.16.54.253"]);
   let maliciousUrl = "www.dropbox.com/scl/fi/tmwi4j86op04r9qo2xdgh/zoomupdate.msi";
   let c2Port = 8041;
   // Union different event types to search for file and network IOCs
   union isfuzzy=true DeviceProcessEvents, DeviceFileEvents, DeviceNetworkEvents
   | where timestamp <= ago(1d)
   | where SHA256 in (maliciousHashes) or (RemoteUrl in (maliciousDomains) or (RemoteUrl has maliciousUrl) or ((RemoteUrl =~ "meeting.bulletmailer.net" or RemoteIP =~ "179.43.176.32") and RemotePort == c2Port))
   | project Timestamp,DeviceName,ActionType,FileName,FolderPath,ProcessCommandLine,InitiatingProcessFileName,InitiatingProcessCommandLine,RemoteUrl,RemoteIP,RemotePort,SHA256,AccountName
```

## How to Investigate?

1. Validate the context of the detection
   - Review the Timestamp and DeviceName to understand when and where the activity occurred
   - Identify which event table generated the match (process, file, or network) based on ActionType
   - Confirm which specific IOC was matched (hash, domain, IP, URL, or port)

2. Analyze process execution details
   - Examine FileName, FolderPath, and ProcessCommandLine for suspicious execution paths or arguments
   - Check InitiatingProcessFileName and InitiatingProcessCommandLine to determine the parent process
   - Look for signs of living-off-the-land binaries, script execution, or user-initiated activity

3. Investigate file activity and lineage
   - Determine whether the malicious hash represents a dropped file, executed binary, or loaded module
   - Correlate file creation, modification, and execution timing with related process events
   - Assess whether the file appears masqueraded as legitimate software or updates

4. Review network communication behavior
   - Analyze RemoteUrl, RemoteIP, and RemotePort to understand outbound connection patterns
   - Check frequency, timing, and sequence of connections to identify beaconing or staging behavior
   - Correlate network activity with the responsible process and user context

5. Assess user and device scope
   - Review AccountName to determine whether activity ran under a standard user or elevated context
   - Check if the same AccountName or DeviceName appears in multiple related events
   - Identify whether activity aligns with expected user behavior or scheduled tasks

6. Correlate with broader activity timeline
   - Build a chronological view of process, file, and network events surrounding the detection
   - Look for precursor activity such as downloads, archive extraction, or script execution
   - Identify follow-on behavior indicating persistence attempts or secondary payload execution
