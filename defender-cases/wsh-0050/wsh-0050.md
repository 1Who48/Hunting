## WSH-0050 Office Add-In Abuse for Initial Access or Persistence

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0050 Office Add-In Abuse for Initial Access or Persistence"_ has been created, how to use it.

### Required Access

These hunting cases are linked through a published application that grants us permission to perform threat hunting via the API in our customers' security portals.

### Custom Changes

* No custom changes are made.

## Overview

This hunting query is designed to identify instances where Microsoft Office applications (such as Word, Excel, PowerPoint, or Access) load add-in files (.xla, .xlam, .vsto, etc.) from non-standard or suspicious locations like user profile directories, temporary folders, downloads, or remote sources. Adversaries often abuse Office add-ins to achieve initial access, code execution, or persistence while blending into normal productivity workflows.

The query reports each add-in only on its **first appearance per device**, rather than on every Office launch. Because Office reloads every registered add-in each time it starts, a same-day baseline is used so an add-in that has already been observed on a device is suppressed on subsequent runs. This prevents the same add-in being re-reported every day while still surfacing genuinely new, low-prevalence, non-vendor add-ins that may indicate malware deployment, phishing payload delivery, or long-term persistence through Office environments.

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **DeviceProcessEvents** module.

### How to Detect?

The **"DeviceProcessEvents"** we can hunt on strange activity based on remote office connections.

### KQL

```kql
let DetectionWindow     = 1d;
let HistoryWindow       = 30d;
let PrevalenceThreshold = 5;
let DetectionStart = ago(DetectionWindow);
let OfficeApps = dynamic(["WINWORD.EXE","EXCEL.EXE","POWERPNT.EXE","MSACCESS.EXE","VSTOInstaller.exe"]);
let SuspiciousExtRe = @"(?i).+\.(wll|xll|ppa|ppam|xla|xlam|vsto)\b";
let SuspiciousPathRe = @"(?i)([A-Z]:\\Users\\[^\\]+\\Temp\\(7z|Rar\$|Temp\.|BNZ\.)|[A-Z]:\\Users\\[^\\]+\\Downloads\\|[A-Z]:\\Users\\[^\\]+\\AppData\\Roaming\\|[A-Z]:\\Users\\Public\\|[A-Z]:\\Windows\\Temp\\|\\\\Device\\|^https?://)";
let TrustedVendorPathRe = @"(?i)([A-Z]:\\Program Files( \(x86\))?\\|[A-Z]:\\Users\\[^\\]+\\AppData\\Local\\Programs\\(Addinsoft|Grammarly|Zoom|Microsoft|Bloomberg|Refinitiv)\\|[A-Z]:\\Oracle\\SmartView\\|[A-Z]:\\ProgramData\\(Logishrd|Microsoft)\\)";
let SuspiciousInitiator = dynamic(["mshta.exe","wscript.exe","cscript.exe","powershell.exe","pwsh.exe","rundll32.exe","regsvr32.exe","certutil.exe","bitsadmin.exe","curl.exe"]);
let AddInLoads = materialize(
    DeviceProcessEvents
    | where Timestamp > ago(HistoryWindow)
    | where FileName in~ (OfficeApps)
    | where ProcessCommandLine matches regex SuspiciousExtRe
    | extend AddInPath = extract(@"(?i)([A-Z]:\\[^""\s]+?\.(?:wll|xll|ppa|ppam|xla|xlam|vsto))", 1, ProcessCommandLine)
    | where isnotempty(AddInPath)
    | where
            ProcessCommandLine matches regex @"(?i)^https?://|\.(wll|xll|vsto)\b.*https?://"
            or (ProcessCommandLine matches regex SuspiciousPathRe and not(AddInPath matches regex TrustedVendorPathRe))
            or InitiatingProcessFileName in~ (SuspiciousInitiator)
    | where not( ProcessCommandLine has ".vsto" and (
              (InitiatingProcessFolderPath matches regex @"(?i)[A-Z]:\\Program Files\\Logitech\\LogiOptions\\" and InitiatingProcessFileName matches regex @"(?i)PlugInInstallerUtility.*\.exe")
           or (InitiatingProcessFolderPath matches regex @"(?i)[A-Z]:\\ProgramData\\Logishrd\\LogiOptions\\Plugins\\VSTO\\[^\\]+\\" and InitiatingProcessFileName =~ "VSTOInstaller.exe")
           or (InitiatingProcessFolderPath matches regex @"(?i)[A-Z]:\\Program Files\\LogiOptionsPlus\\" and InitiatingProcessFileName matches regex @"(?i)PlugInInstallerUtility.*\.exe")
           or (InitiatingProcessFolderPath matches regex @"(?i)[A-Z]:\\ProgramData\\Logishrd\\LogiOptionsPlus\\Plugins\\VSTO\\[^\\]+\\" and InitiatingProcessFileName =~ "VSTOInstaller.exe")
           or (InitiatingProcessFolderPath matches regex @"(?i)[A-Z]:\\Program Files\\Common Files\\microsoft shared\\VSTO\\[^\\]+\\" and InitiatingProcessFileName =~ "VSTOInstaller.exe")
      ))
    | where not( FileName =~ "VSTOInstaller.exe" and ProcessCommandLine has "/Uninstall" )
    | where not( InitiatingProcessFileName =~ "rundll32.exe" and InitiatingProcessCommandLine matches regex @"(?i)[A-Z]:\\WINDOWS\\Installer\\MSI.*\.tmp,zzzzInvokeManagedCustomActionOutOfProc" )
    | where not( FileName =~ "VSTOInstaller.exe" and ProcessCommandLine has "https://dl.getsidekick.com/outlook/vsto/Sidekick.vsto" )
);
let CorporateAddIns =
    AddInLoads
    | summarize DeviceCount = dcount(DeviceId) by AddInPath
    | where DeviceCount >= PrevalenceThreshold
    | project AddInPath;
AddInLoads
| summarize
        LastSeen = max(Timestamp),
        Loads    = count(),
        arg_min(Timestamp, FileName, InitiatingProcessFileName, InitiatingProcessFolderPath, ProcessCommandLine)
    by DeviceName, DeviceId, AddInPath
| project-rename FirstSeen = Timestamp
| where FirstSeen >= DetectionStart
| join kind=leftanti CorporateAddIns on AddInPath
| extend IsMappedDrive = AddInPath matches regex @"(?i)^[D-Z]:\\"
| extend Confidence = case(
        ProcessCommandLine matches regex @"(?i)https?://", "High",
        InitiatingProcessFileName in~ (SuspiciousInitiator), "High",
        AddInPath matches regex @"(?i)\\(Temp|Downloads|AppData\\Roaming|Public)\\", "High",
        IsMappedDrive, "Low",
        "Medium")
| project FirstSeen, LastSeen, Loads, Confidence, DeviceName, DeviceId, FileName, AddInPath, IsMappedDrive, InitiatingProcessFileName, InitiatingProcessFolderPath
| order by Confidence asc, FirstSeen desc
```

## How to Investigate?

1. validate what is new and why it is flagged
   - confirm the add-in type involved (wll, xll, ppa, ppam, xla, xlam, vsto)
   - review first seen, last seen, and event count to understand persistence vs one-off execution
   - verify it is new for that specific device (not present in historical baseline)

2. inspect the add-in path and location risk
   - review the add-in file path and whether it resides in high-risk locations (downloads, appdata, public, programdata, temp, network device paths, or URLs)
   - check whether the path suggests archive extraction staging (7z, rar temp patterns) or user-driven installs
   - determine whether the add-in name/path resembles legitimate software or random/masquerading naming

3. analyze how the add-in was launched
   - identify the office process involved (word, excel, powerpoint, access, vsto installer)
   - review the initiating process name and folder path to understand whether it was opened via explorer/openwith or triggered by scripting (cmd/powershell) or another process
   - assess whether the launch chain aligns with normal user behavior or automation

4. establish provenance and file authenticity
   - determine when and how the add-in file appeared on disk (download, email attachment, browser cache, unzip, installer)
   - validate signer and metadata if available (publisher, version info, compile indicators)
   - check whether the add-in has accompanying files typical of legitimate deployments or looks standalone/suspicious

5. correlate to office child-process and follow-on activity
   - look for office spawning unusual children around first seen (script hosts, powershell, cmd, mshta, rundll32, regsvr32)
   - check for file writes to startup locations, registry changes, scheduled tasks, or other persistence signals after add-in loading
   - review network connections from office processes shortly after add-in execution

6. scope the finding across the estate
   - check whether the same add-in path or filename appears on multiple devices (campaign vs isolated)
   - identify whether the same initiating process pattern repeats across endpoints (same delivery mechanism)
   - compare affected devices/users for shared exposure (same email thread, same download domain, same software rollout)
