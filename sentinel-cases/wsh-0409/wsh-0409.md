## WSH-0409 New Windows Reserved Filenames staged on Office file services

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0409 New Windows Reserved Filenames staged on Office file services"_ has been created, how to use it.

### Required MDR Modules and Sentinel Connectors

| MDR Module                 | Required Data Connectors |
| -------------------------- | ------------------------ |
| **Office Protect**         | Microsoft 365 Defender   |

### Custom Changes

* Custom detection on reserved file names: let Reserved = dynamic(['CON', 'AUX', 'NUL', 'COM1', 'COM2', 'COM3', 'COM4', 'COM5', 'COM6', 'COM7', 'COM8', 'COM9', 'LPT1', 'LPT2', 'LPT3', 'LPT4', 'LPT5', 'LPT6', 'LPT7', 'LPT8', 'LPT9']);
* We have excluded the account "app@sharepoint" from detection as this is a valid account that is used.

## Overview

This hunting case helps identify suspicious reserved filenames from windows on storage.

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Office Protect** module.

### How to Detect?

The **"OfficeActivity"** logs of the customer need to be exported to the Wortell MDR Sentinel Log Analytics Workspace with the Microsoft Sentinel **"Microsoft Defender for Office 365"** connector of Sentinel.

### KQL

```kql
    let starttime = ago(1d);
    let endtime = now();
    let lookback = ago(7d);
    // a threshold can be enabled, see commented line below for PrevSeenCount
    let threshold = 1;
    // Reserved FileNames/Extension for Windows
    let Reserved = dynamic(['CON', 'AUX', 'NUL', 'COM1', 'COM2', 'COM3', 'COM4', 'COM5', 'COM6', 'COM7', 'COM8', 'COM9', 'LPT1', 'LPT2', 'LPT3', 'LPT4', 'LPT5', 'LPT6', 'LPT7', 'LPT8', 'LPT9']);
    OfficeActivity | where TimeGenerated between(starttime..endtime)
    | where isnotempty(SourceFileExtension)
    | where SourceFileName !~ SourceFileExtension
    | where SourceFileExtension in~ (Reserved) or SourceFileName in~ (Reserved)
    | where UserAgent !has "Mac OS"
    | where UserId !has "app@sharepoint"
    | project TimeGenerated, OfficeId, OfficeWorkload, RecordType, Operation, UserType, UserKey, UserId, ClientIP, UserAgent, Site_Url, SourceRelativeUrl, SourceFileName, SourceFileExtension
    | join kind= leftanti (
    OfficeActivity | where TimeGenerated between (lookback..starttime)
    | where isnotempty(SourceFileExtension)
    | where SourceFileName !~ SourceFileExtension
    | where SourceFileExtension in~ (Reserved) or SourceFileName in~ (Reserved)
    | where UserAgent !has "Mac OS"
    | summarize SourceRelativeUrl = make_set(SourceRelativeUrl), UserId = make_set(UserId), SourceFileName = make_set(SourceFileName) , PrevSeenCount = count() by SourceFileExtension
    // To exclude previous matches when only above a specific count, change threshold above and uncomment the line below
    //| where PrevSeenCount > threshold
    | mvexpand SourceRelativeUrl, UserId, SourceFileName
    | extend SourceRelativeUrl = tostring(SourceRelativeUrl), UserId = tostring(UserId), SourceFileName = tostring(SourceFileName)
    ) on SourceFileExtension
    | extend SiteUrlUserFolder = tolower(split(Site_Url, '/')[-2])
    | extend UserIdUserFolderFormat = tolower(replace('@|\\.', '_',UserId))
    // identify when UserId is not a match to the specific site url personal folder reference
    | extend UserIdDiffThanUserFolder = iff(Site_Url has '/personal/' and SiteUrlUserFolder != UserIdUserFolderFormat, true , false )
    | summarize TimeGenerated = make_list(TimeGenerated), StartTime = min(TimeGenerated), EndTime = max(TimeGenerated), Operations = make_list(Operation), UserAgents = make_list(UserAgent),
    OfficeIds = make_list(OfficeId), SourceRelativeUrls = make_list(SourceRelativeUrl), FileNames = make_list(SourceFileName)
    by OfficeWorkload, RecordType, UserType, UserKey, UserId, ClientIP, Site_Url, SourceFileExtension, SiteUrlUserFolder, UserIdUserFolderFormat, UserIdDiffThanUserFolder
    // Use mvexpand on any list items and you can expand out the exact time and other metadata about the hit
    | extend timestamp = StartTime, AccountCustomEntity = UserId, IPCustomEntity = ClientIP
```

## How to Investigate?

1. Validate what triggered the alert logic
   - Confirm the reserved Windows name involved (for example CON, AUX, NUL, COMx, LPTx) and whether it appears as the file name or the extension
   - Review the summarized time range (StartTime to EndTime) and the number of occurrences in the TimeGenerated list
   - Check whether the activity is genuinely new by confirming it was not present in the 7-day lookback set being excluded

2. Review the user and client context
   - Validate the UserId, UserType, and UserKey, and whether the account is a normal end user, admin, service account, or guest
   - Review the ClientIP consistency across the events and whether it matches the user’s normal geography and network patterns
   - Examine the UserAgents list for automation indicators, unusual clients, or uncommon browsers

3. Understand where in SharePoint/OneDrive the activity occurred
   - Review Site_Url and the SourceRelativeUrls list to determine whether this is a personal OneDrive path or a SharePoint site/library
   - Check SiteUrlUserFolder versus UserIdUserFolderFormat to see if the activity is happening in a personal folder that does not match the user identity format
   - Use the UserIdDiffThanUserFolder flag to prioritize cases suggesting access to another user’s personal area or atypical folder targeting

4. Characterize the actions performed on the files
   - Review the Operations list to determine whether the activity represents uploads, file creation, renames, moves, sharing actions, or other content operations
   - Check whether multiple distinct operations occurred in sequence, which can indicate staging behavior rather than a single benign event
   - Compare the pattern of operations to the user’s typical workload and role (for example, bulk document handling vs occasional edits)

5. Examine the file naming patterns and intent
   - Review the FileNames list to identify whether names are random, impersonate system artifacts, or resemble evasion techniques
   - Assess whether the reserved-name pattern appears across multiple files or is isolated to a single object
   - Note any repeated folder paths combined with reserved names, which can indicate a deliberate placement strategy

6. Scope the activity beyond the single summary row
   - Expand the summarized lists (times, operations, URLs, file names) in your investigation workspace to reconstruct the exact sequence of events
   - Determine whether the same UserId or ClientIP appears in similar reserved-name activity across other sites or workloads
   - Document whether the behavior appears opportunistic (single attempt) or systematic (repeated attempts across locations)
