## WSH-0410 Invoke-PowerShellTcpOneLine Usage

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _" WSH-0410 Invoke-PowerShellTcpOneLine Usage"_ has been created, how to use it.

### Required MDR Modules and Sentinel Connectors

| MDR Module                 | Required Data Connectors          |
| -------------------------- | ----------------------------------|
| **Device Protect**         | Windows Security Events via AMA   |

### Custom Changes

* No customer changes are made for this hunt case.

## Overview

Invoke-PowerShellTcpOneLine is a PowerShell script to create a simple and small reverse shell. It can be abused by attackers to exfiltrate data. This query looks for command line activity similar to Invoke-PowerShellTcpOneLine.

### MITRE ATT&CK

This attack tactic can be mapped on the MITRE ATT&CK framework:

| Tactic                | Techniques |
|-----------------------|------------|
| Exfiltration          | T1011      |

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

The **"DeviceActivity"** logs of the customer need to be exported to the Wortell MDR Sentinel Log Analytics Workspace with the Microsoft Sentinel **"Windows Security Events via AMA"** connector of Sentinel.

### KQL

```kql
    SecurityEvent
    | where TimeGenerated > ago(1d)
    | where EventID == 4688
    | where Process has_any ("powershell.exe", "PowerShell_ISE.exe", "cmd.exe")
    | where CommandLine has "$client = New-Object System.Net.Sockets.TCPClient"
    | extend NTDomain = tostring(split(Account,'\\',0)[0]), Name = tostring(split(Account,'\\',1)[0])
    | extend timestamp = TimeGenerated, AccountCustomEntity = Account, HostCustomEntity = Computer, IPCustomEntity = IpAddress
    | extend HostName = tostring(split(Computer, '.', 0)[0]), DnsDomain = tostring(strcat_array(array_slice(split(Computer, '.'), 1, -1), '.'))
    | extend Account_0_Name = Name
    | extend Account_0_NTDomain = NTDomain
    | extend Host_0_HostName = HostName
    | extend Host_0_DnsDomain = DnsDomain
    | extend IP_0_Address = IpAddress
```

## How to Investigate?

1. Validate the process execution details
   - Confirm the exact process name (powershell.exe, PowerShell_ISE.exe, or cmd.exe) and the full command-line content
   - Review the execution timestamp and determine whether it aligns with expected administrative or automation activity
   - Check whether the command line appears truncated or obfuscated beyond the visible TCPClient instantiation

2. Assess the user and privilege context
   - Review the Account, NTDomain, and Name fields to determine whether the execution was performed by an admin, service account, or standard user
   - Determine whether the account typically runs interactive shells on this host
   - Correlate with recent logon activity to identify how the session was established (interactive, remote, scheduled, or service-based)

3. Identify the host role and exposure
   - Review the HostCustomEntity, HostName, and DnsDomain to understand the system’s function (workstation, server, application host)
   - Determine whether scripting and command shells are commonly used on this system type
   - Check whether the host has a history of similar activity or if this is a deviation from baseline behavior

4. Examine potential network intent implied by the command
   - Review the full script or command context to identify destination IPs, ports, or connection logic associated with the TCPClient usage
   - Assess whether the behavior suggests interactive connectivity, tunneling, or scripted communication
   - Note whether the command indicates a one-time connection attempt or a loop-based persistence pattern

5. Correlate with related process and script activity
   - Look for parent processes that launched the shell (for example, explorer.exe, w3wp.exe, services.exe, task scheduler)
   - Identify any child processes or follow-on commands spawned after the initial execution
   - Review nearby script file access or in-memory execution indicators tied to the same account and host

6. Scope for recurrence or broader usage
   - Check whether the same command pattern appears on other hosts or under other accounts within the same time window
   - Determine whether the activity repeats over time, suggesting testing, automation, or staged behavior
   - Document whether this appears to be an isolated execution or part of a coordinated sequence
