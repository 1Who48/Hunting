## WSH-0419 Suspicious Enumeration using Adfind Tool

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0419 Suspicious Enumeration using Adfind Tool"_ has been created, how to use it.

### Required MDR Modules and Sentinel Connectors

| MDR Module                 | Required Data Connectors          |
| -------------------------- | ----------------------------------|
| **Device Protect**         | Windows Security Events via AMA   |

### Custom Changes

* No customer changes are made for this hunt case.

## Overview

Attackers can use Adfind which is an administrative tool to gather information about Domain controllers, ADFS Servers. They may also rename executables with other benign tools on the system.

### MITRE ATT&CK

This attack tactic can be mapped on the MITRE ATT&CK framework:

| Tactic                | Techniques |
|-----------------------|------------|
| Credential Access     | T0059      |
| Discovery             | T1482      |
| Collection            | T1074      |

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

The **"DeviceActivity"** logs of the customer need to be exported to the Wortell MDR Sentinel Log Analytics Workspace with the Microsoft Sentinel **"Windows Security Events via AMA"** connector of Sentinel.

### KQL

```kql
    let lookupwindow = 2m;
    let threshold = 3; //number of commandlines in the set below
    let DCADFSServersList = _GetWatchlist('WS-0243-Agent heartbeat health check failed');
    let tokens = dynamic(["objectcategory","domainlist","dcmodes","adinfo","trustdmp","computers_pwdnotreqd","Domain Admins", "objectcategory=person", "objectcategory=computer", "objectcategory=*"]);
    SecurityEvent
    | where Computer in (DCADFSServersList) // Uncomment to limit it to your DC/ADFS servers list if specified above or any pattern in   hostnames (startswith, matches regex, etc).
    | where EventID == 4688
    | where CommandLine has_any (tokens)
    | where CommandLine matches regex "(.*)>(.*)"
    | summarize Commandlines = make_set(CommandLine, 100), LastObserved=max(TimeGenerated) by bin(TimeGenerated, lookupwindow), Account, Computer, ParentProcessName, NewProcessName
    | extend Count = array_length(Commandlines)
    | where Count > threshold
    | extend NTDomain = split(Account, '\\', 0)[0], Name = split(Account, '\\', 1)[0], HostName = split(Computer, '.', 0)[0], DnsDomain = strcat_array(array_slice(split(Computer, '.'), 1, -1), '.')
    | extend Account_0_Name = Name
    | extend Account_0_NTDomain = NTDomain
    | extend Host_0_HostName = HostName
    | extend Host_0_DnsDomain = DnsDomain
```

## How to Investigate?

1. Validate why the activity crossed the detection threshold
   - Confirm that more than three distinct command lines were executed within the same two-minute window
   - Review the exact time bin and LastObserved timestamp to understand the burst pattern
   - Determine whether the commands appear sequential, iterative, or scripted rather than single ad-hoc executions

2. Analyze the command content and redirection behavior
   - Review each command line in the Commandlines set, focusing on directory enumeration, domain queries, and object category references
   - Note the presence of output redirection (>) and assess whether data was being written to files for later use
   - Identify whether the command syntax resembles built-in discovery utilities, batch scripts, or manual operator input

3. Assess the account and privilege context
   - Review the Account, NTDomain, and Name fields to determine whether the activity was performed by a domain admin, service account, or standard user
   - Determine whether the account normally runs discovery commands on DC or ADFS systems
   - Correlate with recent logon activity to understand how the session was established (interactive, remote, scheduled task)

4. Review the execution chain on the server
   - Examine the ParentProcessName to identify what launched the commands (for example cmd.exe, powershell.exe, services.exe, scheduled task engine)
   - Review the NewProcessName to confirm whether native tools or scripting hosts were used
   - Determine whether the process chain suggests automated reconnaissance or hands-on keyboard activity

5. Evaluate the targeted systems and role sensitivity
   - Confirm that the Computer is a domain controller or ADFS server and assess the sensitivity of running such queries on that role
   - Determine whether similar behavior is expected for maintenance, monitoring, or backup tooling on these systems
   - Compare the activity against historical patterns for the same server role

6. Scope for repetition and campaign-style behavior
   - Check whether the same account executes similar command bursts on other DC/ADFS servers
   - Determine whether the activity repeats across multiple time windows, indicating systematic enumeration
   - Document the sequence: account, host, time window, command themes, and output handling for investigation tracking
