## WSH-0429 Azure Network Security Group NSG Administrative Operations

## Overview

Identifies a set of Azure NSG administrative and operational activities.

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Azure Landingzone** module.

### How to Detect?

The **"AzureActivity"** logs of the customer need to be exported to the Wortell MDR Sentinel Log Analytics Workspace with the Microsoft Sentinel **"Azure Activity"** connector of Sentinel.

### KQL

```kql
    let opValues = dynamic(["Microsoft.Network/networkSecurityGroups/write", "Microsoft.Network/networkSecurityGroups/delete"]);
    // Azure NSG Create / Update / Delete
    AzureActivity
    | where TimeGenerated > ago(1d)
    | where Category =~ "Administrative"
    | where OperationNameValue in~ (opValues)
    | where ActivitySubstatusValue in~ ("Created", "OK","Accepted")
    | sort by TimeGenerated desc
    | extend Name = tostring(split(Caller,'@',0)[0]), UPNSuffix = tostring(split(Caller,'@',1)[0])
    | extend Account_0_Name = Name
    | extend Account_0_UPNSuffix = UPNSuffix
    | extend IP_0_Address = CallerIpAddress
    | project TimeGenerated,Name,CallerIpAddress,Authorization,ResourceGroup,ActivityStatus,OperationName,Resource
```

## How to Investigate?

User Validation
Is the user authorized to do these changes?
if the user is authorized, was the session of the user valid?

- Check audit logs for changes to the user account
- Check interactive and non-interactive logs to validate the session
- Check MFA logs to validate the session

If the user is authorized and the user session is valid check the context of the changes to the azure resource. Are these changes overly permissive? Do these changes threaten the client's infrastrure? If yes, the customer can still be contacted to validate changes.
