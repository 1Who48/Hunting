## WSH-0416 Nishang Reverse TCP Shell in Base64

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0416 Nishang Reverse TCP Shell in Base64"_ has been created, how to use it.

### Required MDR Modules and Sentinel Connectors

| MDR Module                 | Required Data Connectors          |
| -------------------------- | ----------------------------------|
| **Device Protect**         | Windows Security Events via AMA   |

## Overview

This query searches for Base64-encoded commands associated with the Nishang reverse TCP shell.

### MITRE ATT&CK

This attack tactic can be mapped on the MITRE ATT&CK framework:

| Tactic                | Techniques |
|-----------------------|------------|
| Execution             | T1011      |

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

The **"DeviceActivity"** logs of the customer need to be exported to the Wortell MDR Sentinel Log Analytics Workspace with the Microsoft Sentinel **"
Windows Security Evens via AMA"** connector of Sentinel.

### KQL

```kql
    SecurityEvent
    | where TimeGenerated > ago(3d)
    | where EventID == 4688
    | where Process in("powershell.exe","powershell_ise.exe") and CommandLine has "-e" 
    | mv-expand SS = split(CommandLine, " ") 
    | where SS matches regex "[A-Za-z0-9+/]{50,}[=]{0,2}" 
    | extend DecodeString = base64_decode_tostring(tostring(SS)) 
    | extend FinalString = replace("\\0", "", DecodeString) 
    | where FinalString has "tcpclient" and FinalString contains "$" and (FinalString contains "invoke" or FinalString contains "iex") 
    | extend timestamp = TimeGenerated, HostName = split(Computer, '.', 0)[0], DnsDomain = strcat_array(array_slice(split(Computer, '.'), 1, -1), '.')
    | extend Account_0_Name = SubjectUserName
    | extend Account_0_NTDomain = SubjectDomainName
    | extend Host_0_HostName = HostName
    | extend Host_0_DnsDomain = DnsDomain
```

## How to Investigate?

1. Validate the signal and extract the decoded intent
   - Confirm the process creation is PowerShell with an encoded command indicator (-e)
   - Review the extracted base64-like token and ensure it is long enough to be meaningful rather than incidental text
   - Inspect the decoded and cleaned string to understand what the script is attempting to do, focusing on tcpclient usage and invocation patterns

2. Understand the execution context on the host
   - Review the timestamp, HostName, and DnsDomain to determine where the activity occurred and whether that host role commonly runs PowerShell
   - Check whether the activity is isolated to a single machine or occurs across multiple hosts in a short period
   - Note whether the host has other suspicious activity around the same time window that could contextualize the execution

3. Analyze the user and privilege context
   - Review SubjectUserName and SubjectDomainName to determine whether this was run by a standard user, admin, or service account
   - Correlate with recent logon events for the same account to determine whether the session was interactive, remote, or automated
   - Check whether the same user has a history of encoded PowerShell usage or whether this is a deviation from baseline

4. Reconstruct the full process chain and launching mechanism
   - Identify the parent process that launched PowerShell and whether it indicates user initiation, scheduled execution, or application-driven execution
   - Look for signs of script host chaining (for example office apps, wscript/cscript, mshta, rundll32) that commonly precede encoded PowerShell
   - Determine whether additional child processes were spawned after execution that suggest payload staging or follow-on commands

5. Correlate with network indicators implied by tcpclient behavior
   - From the decoded content, extract any referenced IPs, domains, ports, or connection loops and assess whether they appear elsewhere in telemetry
   - Review outbound connection activity from the host near the process start time to see if the script established interactive connectivity
   - Determine whether the timing and connection patterns resemble command-and-control, reverse shell behavior, or scripted administration

6. Assess scope and repetition of the same decoded pattern
   - Compare decoded strings across results to identify reused tooling, common templates, or minor obfuscation variants
   - Check whether the same base64 token or similar decoded content appears under different accounts or hosts
   - Document a concise summary per hit: host, user, decoded intent, parent process, and any associated network indicators
