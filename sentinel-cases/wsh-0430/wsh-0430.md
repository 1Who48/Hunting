## WSH-0430 BitLocker Key Retrieval

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0430 BitLocker Key Retrieval"_ has been created, how to use it.

### Required MDR Modules and Sentinel Connectors

| MDR Module                 | Required Data Connectors |
| -------------------------- | ------------------------ |
| **Identity Protect Cloud** | Azure Active Directory   |

## Overview

Looks for users retrieving BitLocker keys. Enriches these logs with a summary of alerts associated with the user accessing the keys. Use this query to start looking for anomalous patterns of key retrieval

### MITRE ATT&CK

This attack tactic can be mapped on the MITRE ATT&CK framework:

| Tactic                | Techniques |
|-----------------------|------------|
| Credential Access     | T1555      |

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Identity Protect Cloud** module.

### How to Detect?

The **"AuditLogs"** logs of the customer need to be exported to the Wortell MDR Sentinel Log Analytics Workspace with the Microsoft Sentinel **"Azure Active Directory"** connector of Sentinel.

### KQL

```kql
    AuditLogs
    | where TimeGenerated > ago(1d)
    | where OperationName =~ "Read BitLocker key"
    | extend userPrincipalName = tolower(tostring(parse_json(tostring(InitiatedBy.user)).userPrincipalName))
    | extend KeyId = tostring(TargetResources[0].displayName)
    | extend ipAddress = tostring(parse_json(tostring(InitiatedBy.user)).ipAddress)
    | summarize keys_accessed=dcount(KeyId), ipAddresses=make_set(ipAddress) by userPrincipalName
    | join kind=leftouter (SecurityAlert
    | where ProviderName =~ "IPC"
    | extend userPrincipalName = tolower(tostring(parse_json(ExtendedProperties).["User Account"]))
    | summarize user_alert_count=count() by userPrincipalName) on userPrincipalName
    | project userPrincipalName, keys_accessed, ipAddresses, user_alert_count
```

## How to Investigate?

To investigate this use case, check the audit logs and verify if the bitlocker key retrieval was valid.

The valid cases for bitlocker key retrieval are:

- Administrators (example: Intune Admin, Local Device Administrator) for Device Re-registration.
- The owner of the device, normal user accessing the bitlocker keys for their own device.
- Service Principal for Back up purposes.

If the entity accessing the bit locker keys is one of the above then you can also do a session validation.
