## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Azure Landingzone** module.

### How to Detect?

The **"AzureActivity"** logs of the customer need to be exported to the Wortell MDR Sentinel Log Analytics Workspace with the Microsoft Sentinel **"Azure Activity"** connector of Sentinel.

### KQL

```kql
    let opValues = dynamic(["Microsoft.SecurityInsights/alertRules/write", "Microsoft.SecurityInsights/alertRules/delete"]);
    // Microsoft Sentinel Analytics - Rule Create / Update / Delete
    AzureActivity
    | where TimeGenerated > ago(1d)
    | where Category =~ "Administrative"
    | where OperationNameValue in~ (opValues)
    | where ActivitySubstatusValue in~ ("Created", "OK")
    | where Caller != "07d6a2fe-c101-437f-a0f1-38dd4681b1d4"
    | sort by TimeGenerated desc
    | extend Name = tostring(split(Caller,'@',0)[0]), UPNSuffix = tostring(split(Caller,'@',1)[0])
    | extend Account_0_Name = Name
    | extend Account_0_UPNSuffix = UPNSuffix
    | extend IP_0_Address = CallerIpAddress
```

## How to Investigate?

To investigate this use case we need to check if the user is authorized by checking the user identity info. And after this check if the user session is valid.

A user validation check involves analyzing our ws- predefined queries to verify authentication patterns and detect anomalies. For example, interactive and non-interactive login queries help distinguish between manual logins and automated processes, ensuring expected behavior.

MFA and IP MFA queries validate whether multi-factor authentication was successfully applied and whether the login originated from a trusted location.

If inconsistencies are detected, the user session is not deemed valid and the customer needs to be notified.

To investigate this use case, check the activity logs and see what operations has been performed to the mentioned analytic rule. To doublecheck if there are no errors made that could impact the security surface of the customer.
