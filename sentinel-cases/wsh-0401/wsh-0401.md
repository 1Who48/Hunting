## WSH-0401 Sign-ins from IPs that attempt sign-ins to disabled accounts

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WS-0401 Sign-ins from IPs that attempt sign-ins to disabled accounts"_ has been created, how to use it.

### Required MDR Modules and Sentinel Connectors

| MDR Module                 | Required Data Connectors |
| -------------------------- | ------------------------ |
| **Identity Protect Cloud** | Azure Active Directory   |

### Custom Changes

* If there is more than one account targeted and more than one attempts.

## Overview

This usecase Identifies IPs with failed attempts to sign in to one or more disabled accounts. The same IP has then also been used to successfully sign-in on other accounts. This could indicate an attacker who obtained credentials for a list of accounts, and is attempting to login with those accounts - some of which may have already been disabled.

### MITRE ATT&CK

This attack tactic can be mapped on the MITRE ATT&CK framework:

| Tactic                | Techniques |
|-----------------------|------------|
| Initial Access        | T1078      |
| Persistence           | T1098      |
|                       | T1078      |

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Identity Protect Cloud** module.

### How to Detect?

The customer's **"SigninLogs"** and **"AADNonInteractiveUserSigninLogs"** need to be exported to the **Wortell MDR Sentinel Log Analytics Workspace** using the "Azure Active Directory" connector.

To detect failed sign-in attempts for active and disabled accounts, monitor logs with:

* Result type: 50057
* Description: "User account is disabled. The account has been disabled by an administrator"

### KQL

```kql
    let disabledAccounts = _GetWatchlist("WSH-Disabled-Account-Exclusions") | project SearchKey;
    let aadFunc = (tableName:string){
    table(tableName)
    | where TimeGenerated > ago(1d)
    | where ResultType == "50057"
    | extend domain = strcat("@",extract("@(.*)", 1, UserPrincipalName))
    | where domain !in~(disabledAccounts) and UserPrincipalName !in~(disabledAccounts)
    | where ResultDescription =~ "User account is disabled. The account has been disabled by an administrator."
    | mv-expand todynamic(AuthenticationDetails)
    | extend AuthStatusSuccess_ = tostring(AuthenticationDetails.succeeded)
    | where AuthStatusSuccess_ == "true" or AuthStatusSuccess_ == "Auth status unknown"
    | summarize StartTime = min(TimeGenerated),EndTime = max(TimeGenerated),disabledAccountLoginAttempts = count(),disabledAccountsTargeted = dcount(UserPrincipalName),applicationsTargeted = dcount(AppDisplayName),disabledAccountSet = make_set(UserPrincipalName,15),applicationSet = make_set(AppDisplayName,15) by IPAddress,Type,AuthStatusSuccess_
    | where disabledAccountLoginAttempts > 1
    | where disabledAccountsTargeted  > 1
    | order by disabledAccountLoginAttempts desc
    | join kind= leftouter (
    // Consider these IPs suspicious - and alert any related  successful sign-ins
    table(tableName)
    | where ResultType == 0
        | summarize successfulAccountSigninCount = dcount(UserPrincipalName), successfulAccountSigninSet = make_set(UserPrincipalName,15) by IPAddress, Type
    // Assume IPs associated with sign-ins from 100+ distinct user accounts are safe
    | where successfulAccountSigninCount < 100
    ) on IPAddress
    // IPs from which attempts to authenticate as disabled user accounts originated, and had a non-zero success rate for some other account
    | where isnotempty(successfulAccountSigninCount)
    | project StartTime,EndTime,IPAddress,AuthStatusSuccess_,disabledAccountLoginAttempts,disabledAccountsTargeted,disabledAccountSet,applicationSet,successfulAccountSigninCount,successfulAccountSigninSet,Type
    | order by disabledAccountLoginAttempts
    | extend timestamp = StartTime
    };
    let aadSignin = aadFunc("SigninLogs");
    let aadNonInt = aadFunc("AADNonInteractiveUserSignInLogs");
    union isfuzzy=true aadSignin, aadNonInt
    | extend field1 = dynamic_to_json(disabledAccountSet)
    | extend field2 = dynamic_to_json(successfulAccountSigninSet)
    | where field1 != field2
```

## How to Investigate?

To investigate this use case, investigate from where the sign-in attempts were made. In some cases, the sign-in attempts are caused by saved credentials of the disabled account on a (known) device. If the sign-in attemps are coming from a new and unknown IP, then this _might_ indicate an actor trying to force their way in.

Interactive logon sessions are likely old or absent. This is expected due to the account being disabled. Check non-interactive sessions. If found, it likely triggered the alert. This is expected if from a known location.

### Custom Investigation

* This usecase has a GetWatchlist("WSH-Disabled-Account-Exclusions") on all customer where those accounts are known that they are disabled but not removed from the enjoinment.
