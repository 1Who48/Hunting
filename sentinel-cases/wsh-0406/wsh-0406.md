## WSH-0406 Exchange IIS Worker Dropping Webshells

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0406 Exchange IIS Worker Dropping Webshells"_ has been created, how to use it.

### Required MDR Modules and Sentinel Connectors

| MDR Module                 | Required Data Connectors          |
| -------------------------- | ----------------------------------|
| **DeviceFileEvents**       | Windows Security Events via AMA   |

### Custom Changes

* No custom changes are made.

## Overview

IIS worker process (w3wp.exe) is the process that runs IIS app pools (including Exchange IIS virtual directories). If an attacker exploits Exchange or gets code execution in the IIS/Exchange app pool, they often drop a webshell (e.g., .aspx, .ashx, .cshtml) or related tooling into:
inetpub\wwwroot\... Exchange OWA/HttpProxy folders

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

The **"DeviceFileEvents"** logs of the customer need to be exported to the Wortell MDR Sentinel Log Analytics Workspace with the Microsoft Sentinel **"Windows Security Events via AMA"** connector of Sentinel.

### KQL

```kql
  DeviceFileEvents
  | where TimeGenerated > ago(1d)
  | where InitiatingProcessFileName == 'w3wp.exe' | where InitiatingProcessCommandLine contains "MSExchange"
  | where FolderPath has_any ("\\wwwroot\\", "HttpProxy\\owa\\","\\Temporary ASP.NET Files\\")
  | where not(FolderPath has_any("\\tmp\\","\\dl3\\"))
  | where FolderPath !endswith ".log" | where FolderPath !endswith ".json"
  | where FolderPath !endswith ".ini"
  | where FolderPath !endswith ".vb"
  | where FolderPath !endswith '.tmp'
  | where FolderPath !endswith '.xml'
  | where FolderPath !endswith '.js'
```

## How to Investigate?

1. Validate the file activity context
   - Confirm the exact timestamps of the file events and whether they align with normal Exchange/IIS operational hours
   - Review the file operation types (create, modify, rename) to understand what action w3wp.exe performed
   - Note the specific folders involved to determine whether the activity targets application code paths or runtime cache locations

2. Assess why w3wp.exe initiated the file operation
   - Verify the IIS application pool identity associated with the w3wp.exe instance
   - Determine whether the command line referencing MSExchange matches expected Exchange web services behavior
   - Check whether the activity corresponds to a known Exchange feature (OWA, ECP, HttpProxy) or appears out of place

3. Examine file characteristics and intent
   - Review file names, extensions, and sizes to assess whether they resemble web shells, scripts, or compiled payloads
   - Check for unusual naming patterns (random strings, double extensions, uncommon casing)
   - Determine whether the files would be directly accessible via a web request

4. Correlate with process execution and child activity
   - Look for subsequent process creation events originating from the same w3wp.exe instance or IIS worker process
   - Identify whether the file activity is followed by command execution, script engines, or external binaries
   - Evaluate parent-child relationships to understand whether this is isolated file manipulation or part of a larger execution chain

5. Pivot to authentication and web request activity
   - Review Exchange and IIS logs around the same time window for suspicious HTTP methods, anomalous URLs, or authentication failures
   - Check for requests targeting OWA or HttpProxy paths that coincide with the file creation or modification events
   - Determine whether the source IPs and user agents align with expected client behavior

6. Determine scope and prevalence across the environment
   - Check whether similar file paths or file names appear on other Exchange servers or IIS hosts
   - Assess whether the same patterns recur over time or are clustered within a short window
   - Document whether the behavior appears opportunistic, targeted, or consistent with routine platform activity
