## WSH-0418 Suspected LSASS Dump

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0418 Suspected LSASS Dump"_ has been created, how to use it.

### Required MDR Modules and Sentinel Connectors

| MDR Module                 | Required Data Connectors          |
| -------------------------- | ----------------------------------|
| **Device Protect**         | Windows Security Events via AMA   |

### Custom Changes

* No customer changes are made for this hunt case.

## Overview

Look for evidence of the LSASS process being dumped either using Procdump or comsvcs.dll. Often used by attackers to access credentials stored on a system.

### MITRE ATT&CK

This attack tactic can be mapped on the MITRE ATT&CK framework:

| Tactic                | Techniques |
|-----------------------|------------|
| Credential Access     | T1003      |

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

The **"DeviceActivity"** logs of the customer need to be exported to the Wortell MDR Sentinel Log Analytics Workspace with the Microsoft Sentinel **"Windows Security Events via AMA"** connector of Sentinel.

### KQL

```kql
    SecurityEvent 
    | where TimeGenerated > ago(1d)
    | where EventID == 4688
    | where CommandLine has_all ("procdump", "lsass") or CommandLine has_all ("rundll32", "comsvcs", "MiniDump")
    | extend timestamp = TimeGenerated, AccountCustomEntity = Account, HostCustomEntity = Computer
```

## How to Investigate?

1. Validate the process execution and intent
   - Confirm the process creation event (4688) and review the full CommandLine to determine whether it targets lsass.exe via procdump or MiniDump techniques
   - Identify which dumping method was used and whether additional flags or output paths are specified
   - Check whether the command line appears truncated, wrapped, or obfuscated

2. Assess the account and privilege context
   - Review the Account associated with the execution and determine whether it holds administrative or debug-level privileges
   - Correlate with recent logon events to understand how the account session was established (interactive, remote, scheduled)
   - Determine whether the account typically performs memory diagnostics or forensic activity on this host

3. Evaluate the host role and timing
   - Review the HostCustomEntity to understand the system’s function (workstation, server, domain controller)
   - Assess whether the timing aligns with known maintenance, troubleshooting, or incident-response activity
   - Note whether the event occurs during unusual hours for legitimate administrative operations

4. Correlate with related process and file activity
   - Look for child or sibling processes associated with the dump attempt, such as compression utilities or file copy tools
   - Check for nearby file creation events that indicate a dump file was written and possibly moved or accessed
   - Review whether similar commands were executed multiple times in succession, suggesting retries or automation

5. Analyze execution flow and parent process
   - Identify the parent process that launched the dump command to determine whether it was user-initiated or application-driven
   - Assess whether the parent suggests lateral movement, script execution, or abuse of a trusted process
   - Determine whether the process chain indicates manual action or tooling execution

6. Scope for repetition or broader activity
   - Check whether similar lsass dumping commands appear on other hosts or under other accounts within the same timeframe
   - Determine whether the behavior is isolated to a single host or part of a coordinated sequence
   - Document the observed pattern, including host, account, method used, and execution context
