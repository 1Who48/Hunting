## WSH-0421 PowerShell downloads

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0421 PowerShell downloads"_ has been created, how to use it.

### Required MDR Modules and Sentinel Connectors

| MDR Module                 | Required Data Connectors          |
| -------------------------- | ----------------------------------|
| **Device Protect**         | Windows Security Events via AMA   |

### Custom Changes

## Overview

Finds PowerShell execution events that could involve a download.

### MITRE ATT&CK

This attack tactic can be mapped on the MITRE ATT&CK framework:

| Tactic                | Techniques |
|-----------------------|------------|
| Execution             | T1559      |

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

The **"DeviceActivity"** logs of the customer need to be exported to the Wortell MDR Sentinel Log Analytics Workspace with the Microsoft Sentinel **"Windows Security Events via AMA"** connector of Sentinel.

### KQL

```kql
    let ProcessCreationEvents=() {
    let processEvents=SecurityEvent
    | where TimeGenerated > ago(1d)
    | where EventID==4688
    | project  TimeGenerated,ComputerName=Computer, AccountName=SubjectUserName, AccountDomain=SubjectDomainName,FileName=tostring(split (NewProcessName, '_')[-1]), ProcessCommandLine = CommandLine, InitiatingProcessFileName=ParentProcessName,InitiatingProcessCommandLine="",  InitiatingProcessParentFileName="";
    processEvents};
    ProcessCreationEvents
    | where FileName in~ ("powershell.exe", "powershell_ise.exe","pwsh.exe")
    | where ProcessCommandLine has "Net.WebClient"
        or ProcessCommandLine has "DownloadFile"
        or ProcessCommandLine has "Invoke-WebRequest"
        or ProcessCommandLine has "Invoke-Shellcode"
        or ProcessCommandLine contains "http:"
    | project TimeGenerated, ComputerName, AccountName, InitiatingProcessFileName, FileName, ProcessCommandLine
    | top 100 by TimeGenerated
    | extend timestamp = TimeGenerated, HostCustomEntity = ComputerName, AccountCustomEntity = AccountName
```

## How to Investigate?

1. Validate the process execution and why it was flagged
   - Confirm the process is PowerShell (powershell.exe, powershell_ise.exe, or pwsh.exe) and review the full command line
   - Identify which download or web-execution indicator was present (Net.WebClient, DownloadFile, Invoke-WebRequest, http:, Invoke-Shellcode)
   - Check the execution timestamp and whether the activity clusters into a short burst or is spread across the day

2. Extract and profile the network targets implied in the command line
   - Identify any URLs, domains, IP addresses, and paths referenced in the command line
   - Assess whether the target is an internal resource, a known vendor endpoint, or an unfamiliar external destination
   - Note whether the command references direct payload retrieval, script download-and-execute patterns, or staged downloads

3. Review the initiating process chain
   - Examine InitiatingProcessFileName to determine what launched PowerShell (interactive shell, Office app, browser, management agent, service host)
   - Determine whether the initiating process is expected for the host role and user activity at that time
   - Check whether the chain suggests user-driven activity or automated execution (for example scheduled activity patterns)

4. Assess the user and host context
   - Review the AccountName and whether the user commonly runs PowerShell for administrative or operational tasks
   - Identify the ComputerName role (workstation vs server) and whether PowerShell web retrieval is typical for that system
   - Look for evidence of anomalous behavior around the same time for the user or host (unusual logon context, rare tool usage)

5. Correlate with follow-on execution and artifacts
   - Check whether the PowerShell session spawned additional processes shortly after the web request activity
   - Look for file creation events consistent with downloaded content (new scripts, executables, archives) and where they were written
   - Determine whether the command line indicates in-memory execution versus writing payloads to disk

6. Scope and pattern-match across the environment
   - Determine whether the same URL, domain, or command-line pattern appears on other hosts or under other accounts
   - Check whether multiple hosts show similar activity in a coordinated time window
   - Document per hit: host, user, initiating process, network target, and any immediate follow-on behaviors
