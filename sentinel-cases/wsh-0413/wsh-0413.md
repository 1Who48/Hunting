## WSH-0413 Powershell or non-browser mailbox login activity

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _" WSH-0413 Powershell or non-browser mailbox login activity"_ has been created, how to use it.

### Required MDR Modules and Sentinel Connectors

| MDR Module                 | Required Data Connectors |
| -------------------------- | ------------------------ |
| **Office Protect**         | Microsoft 365 Defender   |

### Custom Changes

## Overview

Hunt query to determine if mailbox login was done from Exchange Powershell session.

### MITRE ATT&CK

This attack tactic can be mapped on the MITRE ATT&CK framework:

| Tactic                | Techniques |
|-----------------------|------------|
| Execution             | T1059      |
| Persistence           | T1098      |
| Collection            | T1114      |

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Office Protect** module.

### How to Detect?

The **"OfficeActivity"** logs of the customer need to be exported to the Wortell MDR Sentinel Log Analytics Workspace with the Microsoft Sentinel **"Microsoft Defender for Office 365"** connector of Sentinel.

### KQL

```kql
    OfficeActivity
    | where TimeGenerated > ago(1d)
    | where Operation == "MailboxLogin"
    | where ClientInfoString == "Client=Microsoft.Exchange.Powershell; Microsoft WinRM Client"
    | summarize StartTime = min(TimeGenerated), EndTime = max(TimeGenerated), count() by Operation, OrganizationName, UserType, UserId, MailboxOwnerUPN, Logon_Type, ClientInfoString
    | extend timestamp = StartTime, AccountCustomEntity = UserId
```

## How to Investigate?

To investigate this use case, Detects mailbox login from Exchange PowerShell. All accounts can use it by default, but admins can change it. Whitelist benign activities. But look if non admin is using powershell to connect to exchange, that is in general strange behavior. When a user is making a connection to exchange, check the IP address and if the user have done this before if not our advice is to contact the customer.
