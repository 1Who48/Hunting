## WSH-0422 Suspicious Base64 download activity detected

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0422 Suspicious Base64 download activity detected"_ has been created, how to use it.

| MDR Module                 | Required Data Connectors          |
| -------------------------- | ----------------------------------|
| **Device Protect**         | Windows Security Events via AMA   |

### Custom Changes

## Overview

This hunting query will help detect suspicious encoded Base64 obfuscated scripts that attackers use to encode payloads for downloading and executing malicious files

### MITRE ATT&CK

This attack tactic can be mapped on the MITRE ATT&CK framework:

| Tactic                | Techniques |
|-----------------------|------------|
| Execution             | T1059      |
| Persistence           | T1053      |

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

The **"DeviceActivity"** logs of the customer need to be exported to the Wortell MDR Sentinel Log Analytics Workspace with the Microsoft Sentinel **"Windows Security Events via AMA"** connector of Sentinel.

### KQL

```kql
    Syslog
    | where TimeGenerated > ago(1d)
    | where Facility == 'user'
    | where SyslogMessage has "AUOMS_EXECVE"
    | parse SyslogMessage with "type=" EventType " audit(" * "): " EventData
    | project TimeGenerated, EventType, Computer, EventData
    | where EventType =~ "AUOMS_EXECVE"
    | parse EventData with * "syscall=" syscall " syscall_r=" * " success=" success " exit=" exit " a0" * " ppid=" ppid " pid=" pid " audit_user=" audit_user " auid=" auid " user=" user " uid=" uid " group=" group " gid=" gid "effective_user=" effective_user " euid=" euid " set_user=" set_user " suid=" suid " filesystem_user=" filesystem_user " fsuid=" fsuid " effective_group=" effective_group " egid=" egid " set_group=" set_group " sgid=" sgid " filesystem_group=" filesystem_group " fsgid=" fsgid " tty=" tty " ses=" ses " comm=\"" comm "\" exe=\"" exe "\"" * "cwd=\"" cwd "\"" * "name=\"" name "\"" * "cmdline=" cmdline
    | extend cmdline = trim_end('redactors=.*', cmdline) 
    | where cmdline has "/Basic/Command/Base64/"
    | where exe has_any ("curl", "wget")
    | parse cmdline with * "Base64/" OriginalEncodedCommand: string
    | extend EncodedCommand = extract("((?:[A-Za-z0-9+/-]{4})*(?:[A-Za-z0-9+/-]{2}==|[A-Za-z0-9+/-]{3}=|[A-Za-z0-9+/-]{4}))", 1, OriginalEncodedCommand) 
    | extend DecodedCommand = base64_decode_tostring(EncodedCommand) 
    | project TimeGenerated,Computer,audit_user,user,cmdline,DecodedCommand,EncodedCommand
    | extend timestamp = TimeGenerated
    | extend Host_0_HostName = Computer
    | extend Account_0_Name = user
    | sort by TimeGenerated desc
```

## How to Investigate?

1. Validate the audit event and execution context
   - Confirm the event originates from AUOMS_EXECVE audit records, indicating a process execution on a Linux system
   - Review the timestamp and Computer to determine where and when the execution occurred
   - Verify that the execution was successful based on the success and exit fields parsed from the audit data

2. Analyze the command execution method
   - Confirm that curl or wget was used as the executing binary
   - Review the cmdline to understand how the Base64 payload was delivered via the /Basic/Command/Base64/ path
   - Note whether the execution appears inline, scripted, or chained with other commands

3. Inspect the decoded command content
   - Review the DecodedCommand output to understand the true intent of the execution
   - Identify whether the decoded content performs system discovery, network communication, file manipulation, or follow-on execution
   - Check for signs of automation, obfuscation layers, or command staging

4. Assess the user and privilege context
   - Review audit_user, user, uid, and euid values to determine whether the command ran as root, a privileged account, or a standard user
   - Determine whether the account typically performs command-line network retrieval or script execution
   - Correlate with session (ses) and tty values to identify interactive versus non-interactive execution

5. Correlate with parent and process chain behavior
   - Review ppid and pid relationships to determine what launched curl or wget
   - Assess whether the execution was initiated from a shell, service, cron job, or remote management process
   - Look for nearby executions that suggest a sequence rather than a single isolated command

6. Scope the activity across hosts and time
   - Check whether similar Base64 command patterns appear on other Linux systems within the same timeframe
   - Determine whether the same encoded or decoded command is reused across multiple events
   - Document the pattern observed: host, user, execution method, decoded intent, and timing
