## WSH-0411 Privilege Admin failing Microsoft CA MFA enforcement

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why case _"WSH-0411 Privilege Admin failing Microsoft CA MFA enforcement"_ has been created, how to use it, how to investigate it, and what to do in case of true positive incidents.

### Required MDR Modules and Sentinel Connectors

| MDR Module                       | Required Data Connectors            |
|--------------------------------- |------------------------------------ |
| **Identity Protect Cloud**       | Azure Activity                      |

### Custom Changes

* No custom changes have been made

## Overview

Enhance protection against failed MFA enforcement on privilege admin accounts.

### MITRE ATT&CK

This attack tactic can be mapped on the MITRE ATT&CK framework:

| Tactic                | Techniques |
|-----------------------|------------|
| Credential Access     | T1110      |

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **"Identity Protect Cloud"**

### How to detect?

The **"AzureActivity"** logs of the customer need to be exported to the Wortell MDR Sentinel Log Analytics Workspace with the Microsoft Sentinel **"Azure Activity"** connector of Sentinel.

### KQL

```kql
    let PrivilegeAdmin =
    IdentityInfo
    | where TimeGenerated > ago(14d)
    | where AssignedRoles != "[]" and isnotnull(AssignedRoles)
    | distinct AccountUPN;
    SigninLogs
    | where UserPrincipalName has_any(PrivilegeAdmin)
    | where ResultType == "0"
    | where ConditionalAccessPolicies != "[]"
    | mv-expand ConditionalAccessPolicies
    | extend CADisplayName = tostring(ConditionalAccessPolicies.displayName)
    | extend CAResult = tostring(ConditionalAccessPolicies.result)
    | where CADisplayName == "Microsoft-managed: Multifactor authentication for admins accessing Microsoft Admin Portals"
    | where CAResult == "reportOnlyFailure"
```

## How to investigate?

1. Confirm the administrative identity involved
   - Validate that the UserPrincipalName belongs to an account with assigned privileged roles during the last 14 days
   - Review which roles are associated with the account and whether they grant access to Microsoft admin portals
   - Determine whether the account is a permanent admin or uses eligible/just-in-time elevation

2. Review the successful sign-in context
   - Confirm the sign-in was successful (ResultType 0) and note the exact timestamp
   - Identify which Microsoft admin portal or resource was accessed during the sign-in
   - Review authentication details to understand how the user authenticated (method, device, browser)

3. Analyze the Conditional Access policy evaluation
   - Confirm that the policy evaluated was the Microsoft-managed MFA policy for admins
   - Note that the result was report-only failure, indicating the policy conditions were met but not enforced
   - Review which conditions triggered the failure (for example, MFA not performed, device state, location)

4. Examine user behavior and access patterns
   - Compare the sign-in location, IP address, and user agent against the user’s normal administrative access patterns
   - Check whether the sign-in originated from a known corporate network, VPN, or unfamiliar source
   - Review whether similar report-only failures occur repeatedly for this account

5. Correlate with concurrent administrative activity
   - Review administrative actions performed shortly after the sign-in to understand the potential impact
   - Check for role activation events, configuration changes, or directory modifications in the same session
   - Determine whether activity volume or sensitivity deviates from the user’s normal behavior

6. Scope across other privileged accounts
   - Determine whether multiple privileged users show similar report-only MFA failures within the same timeframe
   - Assess whether the pattern is isolated to a single account or widespread among admins
   - Document whether the behavior aligns with a systemic policy gap or individual usage pattern
