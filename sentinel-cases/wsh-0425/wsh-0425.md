## WSH-0425 MFA Failed and denied

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0425 MFA Failed and denied"_ has been created, how to use it.

### Required MDR Modules and Sentinel Connectors

| MDR Module                 | Required Data Connectors |
| -------------------------- | ------------------------ |
| **Identity Protect Cloud** | Azure Active Directory   |

### Custom Changes

* Detection on the failure login attempts.

## Overview

The MFA failed for the user more than 5 times within 1 hour timeframe.

### MITRE ATT&CK

This attack tactic can be mapped on the MITRE ATT&CK framework:

| Tactic                | Techniques |
|-----------------------|------------|
| Credential Access     | T1111      |

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Identity Protect Cloud** module.

### How to Detect?

The **"SigninLogs"** and **"AADNonInteractiveUserSigninLogs"** logs of the customer need to be exported to the Wortell MDR Sentinel Log Analytics Workspace with the Microsoft Sentinel **"Azure Active Directory"** connector of Sentinel.

### KQL

```kql
    let includedResults = dynamic(["MFA denied; invalid verification code",
    "MFA denied; Verification code already used",
    // "MFA denied; duplicate authentication attempt",
    "MFA denied; user did not select the correct number"]);
    SigninLogs
    | where TimeGenerated > ago(1d)
    | extend MFAStatus_ = tostring(Status.additionalDetails)
    | where MFAStatus_ in(includedResults)
    | where ResultType == 500121
    | summarize result = count() by UserPrincipalName, MFAStatus_, IPAddress, bin(TimeGenerated, 1h)
    | where result > 5
```

## How to Investigate?

Validate the session of the user.
Review Audit changes to the account.
Validate previous MFA and is the MFA method used frequently by the user.
Is the user agent and application use consistent.

When the user session is valid it's no threat. If the user session is not valid, remediation needs to be done and the customer needs to be contacted.
