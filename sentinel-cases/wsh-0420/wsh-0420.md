## WSH-0420 Masquerading files

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0420 Masquerading files"_ has been created, how to use it.

### Required MDR Modules and Sentinel Connectors

| MDR Module                 | Required Data Connectors          |
| -------------------------- | ----------------------------------|
| **Device Protect**         | Windows Security Events via AMA   |

### Custom Changes

* No customer changes are made for this hunt case.

## Overview

Malware writers often use windows system process names for their malicious process names to make them blend in with other legitimate commands that the Windows system executes.

### MITRE ATT&CK

This attack tactic can be mapped on the MITRE ATT&CK framework:

| Tactic                | Techniques |
|-----------------------|------------|
| Execution             | T1569      |

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

The **"DeviceActivity"** logs of the customer need to be exported to the Wortell MDR Sentinel Log Analytics Workspace with the Microsoft Sentinel **"Windows Security Events via AMA"** connector of Sentinel.

### KQL

```kql
    SecurityEvent
    | where TimeGenerated > ago(1d)
    | where NewProcessName endswith "\\svchost.exe"
    | where SubjectUserSid !in ("S-1-5-18", "S-1-5-19", "S-1-5-20")
    | where NewProcessName !has ":\\Windows\\System32"
    | where NewProcessName !has ":\\Windows\\Syswow64"
    | summarize minTimeGenerated=min(TimeGenerated), maxTimeGenerated=max(TimeGenerated), count() by Computer, SubjectUserName, NewProcessName, CommandLine, Account
    | project minTimeGenerated , maxTimeGenerated , count_ , Computer , SubjectUserName , NewProcessName , CommandLine, Account
    | extend NTDomain = tostring(split(Account,'\\',0)[0]), Name = tostring(split(Account,'\\',1)[0])
    | extend HostName = tostring(split(Computer, '.', 0)[0]), DnsDomain = tostring(strcat_array(array_slice(split(Computer, '.'), 1, -1), '.'))
    | extend Account_0_Name = Name
    | extend Account_0_NTDomain = NTDomain
    | extend Host_0_HostName = HostName
    | extend Host_0_DnsDomain = DnsDomain
```

## How to Investigate?

1. Validate why the svchost execution is considered abnormal
   - Confirm that svchost.exe is executing from a non-standard directory outside System32 and SysWOW64
   - Verify that the process is not running under built-in service SIDs (LocalSystem, LocalService, NetworkService)
   - Review the min and max timestamps to understand whether this is a single execution or repeated over time

2. Analyze the executable path and command-line usage
   - Review the full NewProcessName path to determine where the binary resides (user profile, temp directory, application folder)
   - Examine the CommandLine for service group parameters, unusual flags, or missing expected arguments
   - Assess whether the path and invocation pattern resemble masquerading or renamed binaries

3. Assess the user and account context
   - Review SubjectUserName and Account to determine whether this was launched by an interactive user, admin account, or service account
   - Determine whether the account typically runs service-like processes on this host
   - Correlate with recent logon events to understand how the user session was established

4. Review the host role and execution history
   - Identify the Computer role (workstation, server, domain controller) and whether such activity is plausible for that system type
   - Check whether the same NewProcessName appears historically on this host or represents a first-seen binary
   - Review the execution count to assess whether this appears persistent or opportunistic

5. Correlate with related process, service, and file activity
   - Look for parent processes that launched the svchost instance to determine how execution was initiated
   - Check for related service creation, scheduled task creation, or registry changes around the same time window
   - Review nearby file creation or modification events in the same directory as the executable

6. Scope across users and systems
   - Determine whether the same svchost path or command line appears on other hosts or under other accounts
   - Assess whether multiple users on the same host triggered similar activity
   - Document the observed pattern including host, account, path, frequency, and execution context
