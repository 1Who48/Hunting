## WSH-0404 Previously unseen bot or application added to Teams

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0404 Previously unseen bot or application added to Teams"_ has been created, how to use it.

### Required MDR Modules and Sentinel Connectors

| MDR Module                 | Required Data Connectors |
| -------------------------- | ------------------------ |
| **Office Protect**         | Microsoft 365 Defender   |

### Custom Changes

* Exclusions made for  | where AppDistributionMode !has "Organization"

## Overview

This hunting case helps identify new, and potentially unapproved applications or bots being added to Teams.

### MITRE ATT&CK

This attack tactic can be mapped on the MITRE ATT&CK framework:

| Tactic                | Techniques |
|-----------------------|------------|
| Presistance           | T1119      |
| Collection            | T1176      |

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Office Protect** module.

### How to Detect?

The **"OfficeActivity"** logs of the customer need to be exported to the Wortell MDR Sentinel Log Analytics Workspace with the Microsoft Sentinel **"Microsoft Defender for Office 365"** connector of Sentinel.

### KQL

```kql
    let starttime = ago (1d);
    let endtime = ago (1h);
    let lookback = ago(30d);
    let distibutionmode = pack_array("Organization", "Store");
    let historical_bots = (
        OfficeActivity
        | where TimeGenerated between (lookback .. starttime )
        | where OfficeWorkload =~ "MicrosoftTeams"
        | where isnotempty(AddonName)
        | project AddonName);
    OfficeActivity
    | where TimeGenerated between (starttime .. endtime)
    | where OfficeWorkload =~ "MicrosoftTeams"
    | where Operation has "AppInstalled"
    // Look for add-ins we have never seen before
    | where AddonName !in (historical_bots)
    | where AppDistributionMode !in (distibutionmode)
    | extend timestamp = TimeGenerated, AccountCustomEntity = UserId
    | project TimeGenerated,RecordType,Operation,OfficeWorkload,UserId,AddonName,AppDistributionMode
```

## How to Investigate?

To investigate this use case, investigate the application that the user is using for login. Check if you can establish a baseline of the application use. If the user is login from a other IP included an other application, you should reset the password and contact the customer on the action.

### Custom Investigation

* Search on the internet for the added application, if its strange we will contact the customer based on the add-on.

### Standard Investigation Queries

The following queries have to be ran in order to investigate this incident:

* **Known behavior in teams**
