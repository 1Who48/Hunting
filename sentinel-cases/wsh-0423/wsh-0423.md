## WSH-0423 Suspicious Shell script detected

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0423 Suspicious Shell script detected"_ has been created, how to use it.

## Overview

This hunting query will help detect post compromise suspicious shell scripts that attackers use for downloading and executing malicious files.

### MITRE ATT&CK

This attack tactic can be mapped on the MITRE ATT&CK framework:

| Tactic                | Techniques |
|-----------------------|------------|
| Execution             | T1059      |
| Persistence           | T1053      |

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

The **"DeviceActivity"** logs of the customer need to be exported to the Wortell MDR Sentinel Log Analytics Workspace with the Microsoft Sentinel **"Windows Security Events via AMA"** connector of Sentinel.

### KQL

```kql
    Syslog
    | where TimeGenerated > ago(1d)
    | where Facility == 'user'
    | where SyslogMessage has "AUOMS_EXECVE"
    | parse SyslogMessage with "type=" EventType " audit(" * "): " EventData
    | where EventType =~ "AUOMS_EXECVE"
    | project TimeGenerated, EventType, Computer, EventData
    | parse EventData with * "syscall=" syscall " syscall_r=" * " success=" success " exit=" exit " a0" * " ppid=" ppid " pid=" pid " audit_user=" audit_user " auid=" auid " user=" user " uid=" uid " group=" group " gid=" gid "effective_user=" effective_user " euid=" euid " set_user=" set_user " suid=" suid " filesystem_user=" filesystem_user " fsuid=" fsuid " effective_group=" effective_group " egid=" egid " set_group=" set_group " sgid=" sgid " filesystem_group=" filesystem_group " fsgid=" fsgid " tty=" tty " ses=" ses " comm=\"" comm "\" exe=\"" exe "\"" * "cwd=\"" cwd "\"" * "name=\"" name "\"" * "cmdline=" cmdline
    | extend cmdline = trim_end('redactors=.*', cmdline) 
    | where exe has_any ("bash", "dash")
    | where cmdline matches regex "[0-9]{1,3}\\.[0-9]{1,3}\\.[0-9]{1,3}\\.[0-9]{1,3}"
    | where cmdline has "curl" and cmdline has "wget"
    | project TimeGenerated, Computer, audit_user, user, cmdline
    | extend timestamp = TimeGenerated
    | extend Host_0_HostName = Computer
    | extend Account_0_Name = user
    | sort by TimeGenerated desc
```

## How to Investigate?

1. Validate the execution event and shell context
   - Confirm the AUOMS_EXECVE audit record indicates a successful process execution on a Linux host
   - Review the timestamp and Computer to determine when and where the shell command ran
   - Verify that the executing binary is bash or dash rather than a direct curl or wget invocation

2. Analyze the command-line composition
   - Review the full cmdline to identify the embedded IP address and how it is referenced
   - Confirm that both curl and wget appear in the same command line, indicating fallback or chaining logic
   - Assess whether the syntax suggests scripted automation, one-liner execution, or operator-driven input

3. Assess the network intent and targets
   - Identify the external IP address referenced in the command and determine whether it appears elsewhere in telemetry
   - Note whether the command uses direct IP access instead of DNS, which may indicate evasion or simplicity
   - Review whether additional flags imply file retrieval, execution, or piping to the shell

4. Review the user and privilege context
   - Examine audit_user, user, uid, and euid to determine whether the command ran as root or another privileged account
   - Review tty and session (ses) fields to understand whether this was interactive or non-interactive execution
   - Determine whether the account typically runs network-retrieval shell commands on this host

5. Correlate with parent-child and session behavior
   - Use ppid and pid relationships to understand what launched the shell process
   - Check for nearby executions from the same session that suggest a sequence of staged commands
   - Identify whether the shell execution follows a login, remote access event, or scheduled activity

6. Scope and pattern-match across systems
   - Check whether similar bash or dash commands with IP-based curl/wget usage appear on other hosts
   - Determine whether the same command structure or IP address is reused over time
   - Document the pattern including host, user, shell type, command structure, and timing
