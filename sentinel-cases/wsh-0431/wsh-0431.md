## WSH-0431 Execution of File with One Character in the Name

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0431 Execution of File with One Character in the Name"_ has been created, how to use it.

### Required MDR Modules and Sentinel Connectors

| MDR Module                 | Required Data Connectors |
| -------------------------- | ------------------------ |
| **Device Protect**         | Microsoft Defender for Endpoint |
|                            | Azure Active Directory |
|                            | Microsoft 365 Defender |

## Overview

This query detects execution of files with one character in the name (e.g, a.exe, 7.ps1, g.vbs etc.). Normally files that are executed have more characters in the name and this can indicate a malicious file

### MITRE ATT&CK

This attack tactic can be mapped on the MITRE ATT&CK framework:

| Tactic                | Techniques |
|-----------------------|------------|
| Execution             | T1059      |

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

The **"Event"** logs of the customer need to be exported to the Wortell MDR Sentinel Log Analytics Workspace with the Microsoft Sentinel **"Microsoft Defender for Endpoint"** connector of Sentinel.

### KQL

```kql
    Event
    | where TimeGenerated > ago(1d)
    | where EventLog =~ "Microsoft-Windows-Sysmon/Operational" and EventID==1
    | parse EventData with * 'CommandLine">' CommandLine "<" *
    | where CommandLine matches regex @'\\[a-zA-Z0-9]\.[a-zA-Z0-9]{2,5}["]{1}'
    | parse EventData with * 'ProcessGuid">' ProcessGuid "<" * 'Image">' Image "<" * 'Description">' Description "<" * 'OriginalFileName">' OriginalFileName "<" * 'CommandLine">' CommandLine "<" * 'CurrentDirectory">' CurrentDirectory "<" * 'User">' User "<" * 'LogonGuid">' LogonGuid "<" * 'IntegrityLevel">' IntegrityLevel "<" * 'Hashes">' Hashes "<" * 'ParentProcessGuid">' ParentProcessGuid "<" * 'ParentImage">' ParentImage "<" * 'ParentCommandLine">' ParentCommandLine "<" * 'ParentUser">' ParentUser "<" *
    | summarize StartTime = min(TimeGenerated), EndTime = max(TimeGenerated) by EventID, Computer, User, ParentImage, ParentProcessGuid, ParentCommandLine, ParentUser, Image, ProcessGuid, CommandLine, Description, OriginalFileName, CurrentDirectory, Hashes
    | extend NTDomain = tostring(split(User, '\\', 0)[0]), UserName = tostring(split(User, '\\', 1)[0])
    | extend HostName = tostring(split(Computer, '.', 0)[0]), DnsDomain = tostring(strcat_array(array_slice(split(Computer, '.'), 1, -1), '.'))
    | extend Account_0_Name = UserName
    | extend Account_0_NTDomain = NTDomain
    | extend Host_0_HostName = HostName
    | extend Host_0_DnsDomain = DnsDomain
    | extend File_0_Name = Image
```

## How to Investigate?

1. Validate why the process execution was flagged
   - Confirm the event is a Sysmon process creation (EventID 1) and review the StartTime and EndTime range
   - Examine the CommandLine to understand why it matched the regex pattern indicating a suspicious quoted file reference
   - Determine whether the execution represents a single launch or repeated use of the same command

2. Analyze the executable and masquerading indicators
   - Review Image, OriginalFileName, and Description to identify mismatches between file name, metadata, and expected behavior
   - Check whether the executable name or path suggests masquerading, renamed binaries, or execution from unusual directories
   - Review Hashes to understand whether this binary is unique or commonly seen in the environment

3. Examine the command-line and working directory context
   - Inspect the full CommandLine for unusual quoting, escaped paths, chained execution, or suspicious arguments
   - Review CurrentDirectory to determine whether execution occurred from user-writable or temporary locations
   - Assess whether the command structure resembles scripting, loader behavior, or manual operator activity

4. Review the parent process and execution chain
   - Analyze ParentImage and ParentCommandLine to understand what launched the process
   - Determine whether the parent process is expected for the user and host context (for example explorer.exe vs script host)
   - Review ParentUser and LogonGuid to determine whether this execution aligns with an interactive session

5. Assess the user, integrity level, and host context
   - Review User, NTDomain, UserName, and IntegrityLevel to understand privilege level at execution time
   - Identify whether the user typically runs executables from the observed path and with similar command-line patterns
   - Review HostName and DnsDomain to determine whether the host role makes this activity plausible

6. Scope for reuse and pattern consistency
   - Check whether the same Image, CommandLine pattern, or ParentImage appears on other hosts or under other users
   - Determine whether similar quoted-path executions occur repeatedly, suggesting tooling or scripted behavior
   - Document the execution pattern including user, host, binary, parent process, and command-line characteristics
