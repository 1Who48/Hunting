## WSH-0802 File Hash and IP Address (on-demand hunts)

### Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0802 File Hash and IP Address (on-demand hunts)"_ has been created, how to use it.

### Required Access

This Hunting cases are connected via an published application that give us the rights to hunt via the API in the security portal from our customers.

### Custom Changes

No,  

## Overview

Combine usecase WSH-0800 and WSH-0801.

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

The **"DeviceFileEvents"** we will hunt on public access on those servers. 

### KQL

```kql
    let filehash = pack_array("dd13cf13c1fbdc76da63e76adcf36727cfe594e60af0dc823c5a509a13ae1e15", "4c9fa87e72fe59cf15131bd2f3bd7baa7a9555ceec438c1df78dd5d5b8394910");
    let IPs = pack_array("137.175.17.172","172.245.16.125","4.216.93.211","27.102.128.152","45.32.120.181");  
    DeviceFileEvents
    | where Timestamp > ago(7d)
    | where SHA256 in~(filehash)
    | join DeviceNetworkEvents on DeviceName
    | where RemoteIP in(IPs)
    | project Timestamp, DeviceName, ActionType,FileName,InitiatingProcessCommandLine,InitiatingProcessFolderPath,RemoteIP,RemotePort,LocalIP,InitiatingProcessFileName,InitiatingProcessAccountUpn
```

## How to Investigate?

When results always communicate this to the customer. If the IOC is detected on the endpoint the endpoint should by isolated, is its a critical server the customer needs to be contacted first.
Always look on the timeline from the device and always inform the customer. This can be done in the security portal of the customer.
