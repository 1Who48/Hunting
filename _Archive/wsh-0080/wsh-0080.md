## WSH-0080 Detecting stolen session cookies

## Document Classification

This document is only for internal use of Wortell Managed Detection and Response.

## Introduction

The purpose of this document is to explain why usecase _"WSH-0080 Detecting stolen session cookies."_ has been created, how to use it.

### Required Access

These hunting cases are linked through a published application that grants us permission to perform threat hunting via the API in our customers' security portals.

### Custom Changes

Yes, We have excluded local ip addresses on this hunting query.

## Applicability & Technical Requirements

This use case is applicable to customers that subscribe to the Wortell MDR **Device Protect** module.

### How to Detect?

The **"DeviceActivity"** based on the DeviceFileEvents we can hunt on strange activity based on sessions cookies.

### KQL

```kql
    let OfficeHomeSessionIds =
    AADSignInEventsBeta
    | where Timestamp > ago(1d)
    | where ErrorCode == 0
    | where ApplicationId == "4765445b-32c6-49b0-83e6-1d93765276ca" //OfficeHome application
    | where ClientAppUsed == "Browser"
    | where LogonType has "interactiveUser"
    | summarize arg_min(Timestamp, Country) by SessionId;
    AADSignInEventsBeta
    | where Timestamp > ago(1d)
    | where ApplicationId != "4765445b-32c6-49b0-83e6-1d93765276ca"
    | where ClientAppUsed == "Browser"
    | project OtherTimestamp = Timestamp, Application, ApplicationId, AccountUpn, AccountObjectId, AccountDisplayName, OtherCountry = Country, IPAddress, SessionId
    | join OfficeHomeSessionIds on SessionId
    | where IPAddress !="127.0.0.1" and IPAddress !="::1"
    | where OtherTimestamp > Timestamp and OtherCountry != Country
```

## How to Investigate?

The basic premis of this hunt is a user session validation.

- Check the audit log for changes.
- Check the interactive and non-interactive sign ins.
- Application behavior.
- User agent consistency with devices used.
- Location seen before?
- Does the user use OfficeHome more often?

Is the location change legitimate?

If the user is traveling or using a VPN, the change might be expected.

- Sometimes the IP in question is a Microsoft IP this can happen if the user signs in to a Microsoft Application.

### Custom Investigation

Use the following KQL queries to determine if interactive and non-interactive sign-in logs belong to the same device by verifying the deviceId and checking whether it is Azure AD Joined or Registered. There are two queries provided—one for a single session and another for multiple entities under a single customer.

For multiple sessions, fill in all relevant SessionId values and use the filter to analyze each session individually. If a session appears valid, always review the user's audit logs to check for newly registered devices.

**Note: If not all sessions appear in the results, consider setting the maximum query results to MAX.**

'''kql
//Investigate 1 session

//Replace with session token from hunt
let sessiontoken = "Session_Token";  
let nonInteractiveSignIns = AADNonInteractiveUserSignInLogs
| where SessionId == sessiontoken;
let interactiveSignIns = SigninLogs
| where SessionId == sessiontoken;
union nonInteractiveSignIns, interactiveSignIns
| extend deviceDetailsParsed = parse_json(DeviceDetail_string)  // Parse the JSON
| project
    TimeGenerated,
    Category,
    ResultType,
    ResultDescription,
    deviceId = tostring(deviceDetailsParsed.deviceId),  
    trustTypeFromDevice = tostring(deviceDetailsParsed.trustType),
    IPAddress,
    Location, AppDisplayName, ClientAppUsed, ConditionalAccessStatus,
    displayName = tostring(deviceDetailsParsed.displayName),
    UserAgent,
    operatingSystem = tostring(deviceDetailsParsed.operatingSystem),
    browser = tostring(deviceDetailsParsed.browser)
| order by TimeGenerated desc

//Investigate multiple sessions
let sessiontokens = dynamic([
"session_token_1",
"session_token_2",
"session_token_3",
"session_token_4",
"session_token_5",
"session_token_6",
"session_token_7",
"session_token_8",
"session_token_9",
"session_token_10",
"session_token_11",
"session_token_12"
]);
let nonInteractiveSignIns = AADNonInteractiveUserSignInLogs
| where SessionId in (sessiontokens);
let interactiveSignIns = SigninLogs
| where SessionId in (sessiontokens);
union nonInteractiveSignIns, interactiveSignIns
| extend deviceDetailsParsed = parse_json(DeviceDetail_string)
| project
    TimeGenerated,
    SessionId,
    Category,
    ResultType,
    ResultDescription,
    deviceId = tostring(deviceDetailsParsed.deviceId),  
    trustTypeFromDevice = tostring(deviceDetailsParsed.trustType),
    IPAddress,
    Location,
    AppDisplayName,
    ClientAppUsed,
    ConditionalAccessStatus,
    displayName = tostring(deviceDetailsParsed.displayName),
    UserAgent,
    operatingSystem = tostring(deviceDetailsParsed.operatingSystem),
    browser = tostring(deviceDetailsParsed.browser)
| order by SessionId, TimeGenerated
'''
